# VibeWrite 提测报告

## 版本信息
- 提测日期：2026-04-06
- 变更主题：`startDraft` / `continueWriting` 的 metadata 改为 structured tool output

## 变更范围
- 正文请求保持流式输出，metadata 仍然作为正文完成后的第二阶段请求。
- metadata 不再依赖正文尾部 `[[VIBEWRITE_METADATA]]` 文本块，而是强制调用 `emit_metadata` 工具并直接读取结构化参数。
- `summary`、`nextFocus`、`suggestionChips` 只接受真实模型返回，不做 fallback 伪造。
- `edit` 路径不纳入本次结构化输出改造。

## 交互预期
- `startDraft` 和 `continueWriting` 的正文仍然先流式完成。
- 正文网络流结束后会立刻发起 metadata 请求，metadata 可以和正文尾部 playback 并行等待。
- 正文 playback 收尾期间，Subtitle 和发送按钮继续保持“AI 思考中”状态。
- metadata 还没回来时，建议区域只显示轻量的 `建议生成中` 胶囊。
- metadata 成功后才刷新建议区域。
- metadata 失败时，建议区域保持空白，不伪造建议，不显示显式错误态。
- `edit` 路径应保持原有行为，不受 structured output 影响。

## QA 验收点
- 确认正文流式体验未退化。
- 确认 metadata 请求使用 structured tool output，而不是文本 JSON 解析。
- 确认 metadata 成功后才刷新建议区域。
- 确认 metadata 失败时建议区域保持空，不出现假 chips。
- 确认 `edit` 路径没有被这次改造影响。

## 建议验证步骤
- 打开一个项目，触发 `startDraft`。
- 观察正文完成后，Subtitle 和发送按钮是否继续维持思考态，直到正文 playback 真正收尾，然后建议区域再更新。
- 在同一项目中触发 `continueWriting`。
- 观察正文完成后，Subtitle 和发送按钮是否继续维持思考态，直到正文 playback 真正收尾，然后建议区域再更新。
- 使用 metadata 失败场景验证建议区域是否保持空白。
- 走一次 `edit` 选区编辑，确认行为与改造前一致。

## 验收结论
- 本地测试已通过，structured metadata 路径已替换掉旧的文本 JSON 解析方式。
- 这份提测单建议 QA agent 独立复核正文流式时序、structured metadata 返回和 metadata 失败空态表现。
- 若后续再遇到正文或建议异常，请保留 runtime AI 日志中的 trace id、prose network / playback timing，以及 metadata request / tool decode timing，便于直接区分时序问题与模型返回问题。
