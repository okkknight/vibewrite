# VibeWrite 提测报告

## 版本信息
- 目标提交：`97f8b08`
- 提测日期：2026-04-06
- 变更主题：`startDraft` / `continueWriting` 改为“正文请求 / metadata 请求”双请求方案

## 变更范围
- 正文请求保持流式输出，prose 结束后立即异步请求 metadata，metadata 可以和正文流式收尾并行等待。
- metadata 只负责 `summary`、`nextFocus`、`suggestionChips`，不再依赖正文尾部 `[[VIBEWRITE_METADATA]]` block。
- `edit` 路径保持原有行为，不纳入本次拆分。
- 不修改 UI 视觉、不改文档存储模型、不碰 selection/edit 路径之外的交互语义。

## 交互预期
- `startDraft` 会先看到正文流式生成完成，建议区域在 metadata 返回后异步刷新；正文流式收尾期间，Subtitle 和发送按钮仍应保持“AI 正在思考”态，直到流式 playback 真正结束。
- `continueWriting` 会先看到正文流式生成完成，建议区域在 metadata 返回后异步刷新；正文流式收尾期间，Subtitle 和发送按钮仍应保持“AI 正在思考”态，直到流式 playback 真正结束。
- metadata 仍未返回时，建议区域显示轻量的 `建议生成中` 提示即可，不要伪造 chips，也不要升级成显式错误态。
- metadata 请求失败时，建议区域保持空白，不伪造建议，不显示显式错误提示。
- `edit` 仍按现有路径工作，不应出现这次双请求逻辑的副作用。

## QA 验收点
- 确认正文流式体验未退化。
- 确认 metadata 是正文完成后的第二个独立请求。
- 确认 metadata 成功后才刷新建议区域。
- 确认 metadata 失败时建议区域保持空，不出现假 chips。
- 确认 `edit` 路径没有被这次改造影响。

## 建议验证步骤
- 打开一个项目，触发 `startDraft`。
- 观察正文流式结束后，Subtitle 和发送按钮是否继续维持思考态，直到正文 playback 真正收尾，然后建议区域再更新。
- 在同一项目中触发 `continueWriting`。
- 观察正文流式结束后，Subtitle 和发送按钮是否继续维持思考态，直到正文 playback 真正收尾，然后建议区域再更新。
- 使用 metadata 失败场景验证建议区域是否保持空白。
- 走一次 `edit` 选区编辑，确认行为与改造前一致。
