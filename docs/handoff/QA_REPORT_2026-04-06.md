# QA Report: Metadata Prompt Tightening

## Goal
Verify the prompt tightening that prioritizes `suggestionChips` and keeps `globalSynopsis` short and stable, so the metadata request is less likely to crowd out the suggestion chips.

## Reference
- Commit: current worktree changes
- Current date: `2026-04-06`

## Scope
Review and verify only the metadata prompt tightening.

Do not reopen unrelated UI polish, shell layout, or earlier metadata-routing work unless a regression is observed.

## What changed
- The metadata prompt now treats `suggestionChips` as the highest-priority output.
- `globalSynopsis` is now described as short and stable, and should not repeat `localSummary`.
- The Anthropic-compatible tool schema and the MiniMax text-schema descriptions were both aligned with that priority.
- Handoff docs were updated to reflect the tighter prompt wording.

## Verification checklist
1. Open the prompt builder and confirm the metadata instructions now prioritize `suggestionChips`.
2. Confirm the system and user prompts no longer ask `globalSynopsis` to compete with chip generation.
3. Confirm the tool/schema descriptions match the prompt wording.
4. Run `startDraft` and `continueWriting` and confirm the runtime logs still report metadata success or failure with `suggestionCount`.
5. Confirm the suggestion area still only shows real metadata output and does not fabricate fallback chips.

## What to look for in logs
- Metadata request logs should still show:
  - `localSummaryCount`
  - `globalSynopsisCount`
  - `nextFocusCount`
  - `suggestionCount`
- Successful metadata responses should continue to report `suggestionCount=3`.
- Failures should still show the same structured metadata error path, but with the new prompt wording in effect.
