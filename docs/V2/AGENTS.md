# VibeWrite V2 AGENTS

## 1. 这份文档是干什么的

这份文档是 VibeWrite V2 阶段的 agent 操作指南。

它的作用是告诉后续 Codex / coder-flow：

- 当前 V2 研发应以哪些文档为准
- 哪些设计原则不能打破
- 做功能时应该优先什么
- 哪些旧版本思路已经不适合继续沿用

如果和 V1 文档冲突，一律以 V2 文档为准。

---

## 3. V2 产品定位

VibeWrite V2 是一个：

- 以正文为中心的极简 AI 写作协作器
- 优先服务 `startDraft / continueWriting / edit`
- 允许局部 patch，而不是全文重写
- UI 上更像安静的文本编辑器，而不是工作台

V2 不是：

- 通用聊天产品
- 重型写作平台
- 项目管理工具
- 多模式、多入口写作系统

---

## 4. V2 的核心原则

### 4.1 正文优先

- 正文永远是主视觉
- AI、历史、版本、选区工具都是辅助层
- 不要把辅助层做成主页面

### 4.2 动作少，语义交给 LLM

- 系统不做复杂语义规则系统
- 不要用关键词路由去硬分类用户意图
- 系统只提供必要上下文和用户原始 prompt

### 4.3 输出要短，契约要清晰

- `1024 token` 是体验预算
- 起稿与续写要尽量短
- 编辑优先走局部 patch

### 4.4 局部编辑必须是真局部

- 选区编辑不能退化成整篇重写
- patch 过程中要锁定目标文本
- 输出应尽量是局部替换信息，而不是全文

### 4.5 UI 必须安静

- 少按钮
- 少跳转
- 少分区
- 少显性模式切换

---

## 5. V2 只保留的三类动作

V2 只保留：

1. `startDraft`
2. `continueWriting`
3. `edit`

### `startDraft`

- 新会话起稿
- 只生成开头或第一段
- 不生成完整大纲或全文

### `continueWriting`

- 基于已有正文推进下一段
- 只续写局部，不重写全文

### `edit`

- 对已有正文做局部修改
- 优先通过选区触发
- 返回 patch 或局部替换结果

---

## 6. V2 研发规则

### 6.1 先看文档，再动手

每次做任务前，优先检查：

- `PRD2.0.md`
- `IA2.0.md`
- `UI2.0.md`
- `Wireframes2.0.md`
- 当前任务文档
- 最新 handoff

### 6.2 不要恢复 V1 思路

以下内容不要再作为主结构引入：

- “先讨论再起稿”主分流
- 工作台式双栏主界面
- 多语义快捷按钮墙
- 扩写 / 缩写 / 润色独立动作入口
- 以对话为中心的首页

### 6.3 不要提前扩展

当前阶段不要主动扩展：

- 长篇章节树
- 人物设定库
- 模板市场
- 作品集管理
- 多端同步
- 团队协作

### 6.4 先骨架，后增强

优先级顺序：

1. 页面骨架
2. 主动作路径
3. 局部 patch
4. 回退与版本
5. AI 接入与流式体验

### 6.5 让 UI 服务写作，而不是服务功能展示

- UI 的核心不是展示能力
- UI 的核心是让作者持续写下去

---

## 7. 推荐的实现节奏

### 第 1 步：页面骨架

- 首页起稿页
- 写作会话页
- 正文编辑区
- AI / 历史 / 版本辅助层

### 第 2 步：动作模型

- `startDraft`
- `continueWriting`
- `edit`

### 第 3 步：局部 patch

- 选区
- 上下文切片
- patch 返回
- 正文局部替换

### 第 4 步：回退与版本

- 线性 revision history
- 撤销
- 对比
- 重试

### 第 5 步：真实 AI

- 适配真实请求协议
- 保持短输出
- 保持体验优先

---

## 8. 给 coder 的执行提示

如果你是接手 V2 的 coder agent，请始终记住：

- 先读 V2 文档
- 以正文为中心
- 不要把产品做回工作台
- 不要把局部编辑做成全文重写
- 不要增加新的主入口，除非 PRD 明确要求
- 做完每个阶段，先 review 再扩展下一阶段
