# VibeWrite Wireframes 2.0

## 文档目的

本文件用于指导 VibeWrite V2 的低保真页面骨架与交互结构。

它不是视觉稿，也不是组件清单。重点是：

- 页面信息层级
- 主次关系
- 关键交互
- 哪些能力应该安静地收进辅助层

请务必按以下原则理解：

- 这个产品首先是一个文本编辑器
- AI 能力是编辑器的增强模块，不是主舞台
- 页面应该像一张安静的白纸，而不是工作台
- 不要把它实现成普通聊天产品
- 不要把它实现成重型写作工具链

---

## 1. Wireframe 总原则

### 1.1 白纸优先

- 用户进入页面时，第一感受应该是“可以直接开始写”
- 空状态要轻，不要像控制面板
- 辅助能力可以存在，但默认不抢戏

### 1.2 正文优先

- 正文始终是唯一主舞台
- 所有 AI、历史、版本、选区辅助能力都围绕正文展开
- 任何时候都不应让辅助层压过正文

### 1.3 安静优先

- 少按钮
- 少分区
- 少跳转
- 少模式切换
- 少显性语义判断入口

### 1.4 渐进披露

- 默认只展示最必要的结构
- AI、历史、版本、选区工具都应该按需展开
- 用户选中文本、需要回退、需要补写时，再显性出现相关能力

### 1.5 单主线

V2 的主线只有一条：

`直接起稿 -> 续写 -> 局部编辑`

不要在 UI 上重新引入“先讨论再起稿”的主分流。

---

## 2. 顶层页面结构

V2 顶层只保留两个主页面：

1. 首页 / 起稿页
2. 写作会话页

可选存在：

- 极简设置页

但设置页不应进入主流程。

---

## 3. 页面 1：首页 / 起稿页

### 3.1 页面目标

首页只负责两件事：

1. 快速开始一篇新写作
2. 回到最近会话继续写

它不是项目管理页，不是卡片工作台，不是导航中心。

### 3.2 页面气质

- 像一张首页笔记纸
- 像写作本的封面页
- 轻、空、安静

### 3.3 首页骨架

```text
┌──────────────────────────────────────────────────────────────────────┐
│ VibeWrite                                              [新建写作]    │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  直接起稿                                                            │
│  ┌──────────────────────────────────────────────────────────────┐    │
│  │ 输入一句想法、主题或开头要求                                  │    │
│  │                                                              │    │
│  │ [______________________________________________]             │    │
│  │                                          [开始写作]           │    │
│  └──────────────────────────────────────────────────────────────┘    │
│                                                                      │
│  最近会话                                                            │
│  ┌──────────────────────────────────────────────────────────────┐    │
│  │ 标题：成年人孤独感                                  [继续写] │    │
│  │ 一句话摘要：克制随笔，正在收紧开头                              │    │
│  │ 更新时间：6 分钟前                                              │    │
│  └──────────────────────────────────────────────────────────────┘    │
│                                                                      │
│  ┌──────────────────────────────────────────────────────────────┐    │
│  │ 标题：雨夜重逢                                      [继续写] │    │
│  │ 一句话摘要：小说场景，已写到重逢后的第一段对话                  │    │
│  │ 更新时间：昨天                                                  │    │
│  └──────────────────────────────────────────────────────────────┘    │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘
```

### 3.4 首页模块说明

#### A. 顶部栏

包含：

- 产品名 `VibeWrite`
- `新建写作`

原则：

- 顶部栏只保留最轻入口
- 不加入复杂导航
- 不加入侧边菜单

#### B. 直接起稿区

这是首页唯一主入口。

交互：

- 用户输入一句需求
- 点击 `开始写作`
- 进入新的写作会话页
- 直接进入 `startDraft` 流程

这里不要出现：

- “先讨论再起稿”
- 多种起稿模式卡片
- 模式墙

#### C. 最近会话区

最近会话用于回到上次的正文协作状态。

每个会话建议展示：

- 标题
- 一句话摘要
- 更新时间
- 当前阶段标签
- `继续写`

最近会话是恢复入口，不是文件管理入口。

#### D. 空状态

当没有任何会话时：

- 仅显示一条轻提示
- 保留一个明显但不喧宾夺主的起稿输入区
- 不要显示模板市场
- 不要显示功能导览墙

### 3.5 首页非目标

不要实现：

- 标签筛选
- 文件夹
- 复杂搜索
- 模板中心
- 作品库
- 多入口模式分流

---

## 4. 页面 2：写作会话页

### 4.1 页面目标

围绕单篇内容完成：

- 起稿
- 续写
- 局部编辑
- 版本回退

### 4.2 页面气质

- 像一个安静的文本编辑器
- 像一本正在写的笔记本
- 不是聊天客户端
- 不是项目工作台

### 4.3 会话页默认结构

推荐采用：

- 中央：正文编辑区
- 左侧：AI 侧栏
- 右侧：历史 / 版本侧栏
- 顶部：极简状态栏
- 底部：轻量输入区或工具区
- 选中文本时：浮层动作

关键点：

- 正文永远是视觉中心
- 辅助层默认收起或弱化
- 不要做成左右等权双栏工作台

### 4.4 会话页骨架

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ ← 返回   会话标题                                        正在正文协作   [···] │
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  [AI 侧栏折叠按钮]          ┌────────────────────────────────────────────┐  │
│                              │ 正文编辑区                                  │  │
│                              │                                            │  │
│                              │  成年人真正感到孤独的时候，未必是在深夜。   │  │
│                              │  更多时候，是在一个很普通的傍晚……         │  │
│                              │                                            │  │
│                              │  ……                                         │  │
│                              │                                            │  │
│                              └────────────────────────────────────────────┘  │
│                                                                              │
│                                                       [历史/版本折叠按钮]   │
├──────────────────────────────────────────────────────────────────────────────┤
│  输入框：继续写 / 编辑这段 / 把这句改得更克制一点                              │
│  [____________________________________________]   [发送]                    │
└──────────────────────────────────────────────────────────────────────────────┘
```

这个骨架强调的是：

- 正文始终占据中心
- 辅助层是可收缩的
- 输入区是低存在感的
- 操作不应分散在很多固定按钮上

---

## 5. 会话页的核心区域

## 5.1 顶部栏

顶部栏只负责最轻的状态与入口。

建议包含：

- 返回首页
- 会话标题
- 当前状态
- AI / 历史侧栏开关
- 更多操作

不要包含：

- 大量固定工具按钮
- 多模式切换
- 大型功能分区

顶部栏更像笔记本页眉，而不是控制台工具条。

---

## 5.2 正文编辑区

正文编辑区是唯一主舞台。

### 责任

- 承载当前写作内容
- 承载手动编辑
- 承载 AI 结果的最终落点

### 视觉要求

- 最大面积
- 最低干扰
- 充分留白
- 适合长时间阅读和编辑

### 编辑规则

- 用户可以直接在正文里改
- AI 结果要直接写回正文
- 不要让用户在对话里看一遍，再手工搬运到正文

### 文本选区

选中文本后，正文区域应允许出现轻量浮层。

浮层不应成为固定工具面板，而应是按需出现的上下文工具。

---

## 5.3 AI 侧栏

AI 侧栏承载的是协作流，不是独立聊天产品。

### 内容

- 用户输入记录
- AI 回复
- AI 的轻量建议
- 正在进行的任务说明

### 行为

- 默认收起
- 需要时从左侧展开
- 收起时不占用正文注意力

### 气质

- 像旁边的一本协作便签
- 不是 IM 聊天窗
- 不是独立消息中心

---

## 5.4 历史 / 版本侧栏

历史和版本应该被收进右侧辅助层。

### 内容

- 最近会话
- 局部 patch 历史
- 撤销
- 前后对比
- 本段重试

### 行为

- 默认收起
- 需要回退或对比时展开

### 设计要求

- 历史是辅助回看，不是主舞台
- 不要做成复杂树状版本管理
- 第一版只需要线性回退和对比

---

## 5.5 底部输入区

底部输入区承载用户的自然语言协作指令。

### 作用

- 起稿时输入主题
- 续写时输入推进要求
- 编辑时输入修改意图

### 约束

- 输入区要低存在感
- 不是一整块聊天面板
- 不是对话主舞台

### 文案建议

占位提示可以类似：

- `继续写`
- `把这段改得更克制一点`
- `往下写一段，让情绪慢一点出来`

---

## 6. 核心交互状态

## 6.1 起稿态

### 场景

用户从首页进入一个新会话，准备让 AI 开头。

### UI 表现

- 正文区像白纸
- 顶部状态显示“起稿中”
- AI 侧栏可收起
- 输入区保留一句简短提示

### 交互原则

- 只生成开头
- 不做全文
- 不做大纲中心

---

## 6.2 续写态

### 场景

用户基于已有正文继续往下写。

### UI 表现

- 正文已存在
- 当前写作位置可以被轻量标记
- 底部输入区可直接输入续写要求

### 交互原则

- 每次只推进下一段或下一场景
- 不要求全文重写
- 不把续写做成独立复杂模式

---

## 6.3 编辑态

### 场景

用户在正文里选中某段文本，想做局部修改。

### UI 表现

- 选区高亮
- 选区附近出现轻量浮层
- 可选择“在对话中修改这段”
- patch 生成期间目标区域可以锁定

### 交互原则

- 局部编辑必须是真正局部
- 不让模型返回整篇文章
- 不让用户被带离正文

---

## 6.4 回退态

### 场景

用户要撤销、对比、或重试上一轮修改。

### UI 表现

- 右侧历史 / 版本侧栏展开
- 当前变更与前一版可对照
- 提供一键回退或重试

### 交互原则

- 回退应该随手可得
- 但不能变成复杂版本树工作台

---

## 7. 选区浮层

选中文本后出现的浮层应极轻。

### 目的

- 让局部修改自然出现
- 让 patch 意图明确
- 让用户不必离开正文

### 浮层建议项

- 在对话中修改这段
- 续写这段
- 重写这段

### 浮层要求

- 靠近选区
- 小体积
- 短停留
- 不要做成大型菜单

### 说明

浮层只是入口，不是主面板。

---

## 8. 响应式 / 窗口变化

V2 主要跑在 macOS 桌面端，但窗口尺寸会变化。

### 建议

- 窗口较宽时，侧栏可以左右展开
- 窗口较窄时，侧栏应改为抽屉覆盖
- 正文区域优先保留空间
- 不要因为显示辅助层就压缩正文到不可读

### 核心原则

正文优先，辅助层让位。

---

## 9. 文案与状态提示

### 轻提示原则

- 提示要短
- 提示要安静
- 提示要帮用户理解下一步，而不是解释产品体系

### 推荐状态文案

- `起稿中`
- `正文协作中`
- `局部修改中`
- `正在回退`

### 不推荐

- 大段产品说明
- 复杂 onboarding
- 功能列表式提示

---

## 10. 不要实现的内容

以下内容在 V2 Wireframe 中都不应成为主结构：

- 工作台式双栏主界面
- 以对话为中心的首页
- “先讨论再起稿”主分流
- 多语义快捷按钮墙
- 扩写 / 缩写 / 润色独立按钮组
- 复杂模式切换栏
- 项目管理面板
- 作品库
- 模板市场
- 多章节树
- 重型版本树

---

## 11. 页面优先级

### 第一优先级

- 首页起稿区
- 写作会话页骨架
- 正文编辑区
- AI 侧栏
- 历史 / 版本侧栏
- 选区浮层

### 第二优先级

- 最近会话列表
- 底部输入区
- 回退与对比入口
- 更多操作

### 第三优先级

- 细节视觉优化
- 更完整的空状态文案
- 更丰富的辅助提示

---

## 12. 完成标准

Wireframes 2.0 的实现完成后，应至少满足：

1. 首页像一张安静的起稿页，不像工作台
2. 直接起稿是唯一主入口
3. 写作会话页以正文为视觉中心
4. AI、历史、版本都以可收缩辅助层存在
5. 选中文本后能出现轻量局部编辑浮层
6. 局部编辑以 patch 思路工作，不以全文重写为常态
7. 页面整体气质符合“编辑器优先、安静、不打扰写作”
