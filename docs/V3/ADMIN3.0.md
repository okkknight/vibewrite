# VibeWrite 管理后台 3.0

## 1. 后台定位

这是一个给单人运维用的极简后台，不是完整管理系统。

目标只有四个：

- 看请求
- 改密钥
- 改 AI system prompt 配置
- 看和改限额

---

## 2. 登录方式

后台只需要一个简单登录：

- 单个管理员账号
- 单个密码
- 后端环境变量配置
- 登录后使用 session cookie

不做：

- 多账号
- 角色权限
- 邀请机制
- 二步验证

---

## 3. 页面结构

### 3.1 总览

显示：

- 今日请求数
- 今日成功率
- 今日超限数
- 当前活跃设备数
- 当前模型和 provider

### 3.2 请求列表

显示每条请求的：

- 请求时间
- 设备 ID
- action
- 耗时
- 状态
- 错误码
- token 统计

支持点击查看详情，但不显示正文原文。

### 3.3 密钥页

用于：

- 查看当前 provider API key 是否存在
- 查看当前 admin 登录名
- 更新 provider API key
- 更新 admin 登录凭证

第一版只做当前值查看和更新，不做密钥版本树、轮换流程或禁用旧密钥。

### 3.4 AI System Prompt 页

用于：

- 查看当前 `templateBody`
- 查看当前 `actionRulesJson`
- 查看当前 `modelContextRulesJson`
- 更新当前 `templateBody`
- 更新当前 `actionRulesJson`
- 更新当前 `modelContextRulesJson`

第一版只做当前生效值查看和更新，不做多版本发布、草稿、回滚或历史比较。

### 3.5 限额页

用于：

- 设置日限额
- 设置周限额
- 查看已用量
- 手动封禁设备

### 3.6 设备页

用于：

- 查看设备列表
- 查看设备请求量
- 临时封禁设备
- 解除封禁

---

## 4. 后台要看到什么

后台必须能快速回答这些问题：

- 这个设备今天还剩多少额度
- 这个请求为什么失败
- 当前密钥是否可用
- 当前 AI system prompt 配置是什么
- 哪些设备正在频繁请求

---

## 5. 后台不要做什么

- 不展示正文原文
- 不展示摘要原文
- 不做富文本编辑
- 不做复杂图表
- 不做审批流
- 不做多人协作

---

## 6. 操作约束

所有后台修改都必须记录审计日志，包括：

- 操作人
- 时间
- 修改项
- 修改前后差异摘要

但审计日志也不要记录正文原文。

---

## 7. 最小可用版本

后台第一版只要能做到：

1. 登录
2. 看请求
3. 改密钥
4. 改 AI system prompt 配置
5. 改限额
6. 封禁设备

这就够上线。
