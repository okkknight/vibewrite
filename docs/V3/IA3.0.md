# VibeWrite IA 3.0

## 1. 信息架构总览

V3 的系统分成四层：

1. 前端编辑器壳子
2. 后端 AI 网关
3. 后台管理页面
4. 基础存储与监控

---

## 2. 前端负责什么

前端只保留和用户直接相关的能力：

- 正文编辑器
- 本地 Markdown 文件打开、保存、另存为
- 最近打开记录
- 离线编辑
- AI 请求入口和流式渲染
- AI 不可用时的提示

前端不负责：

- AI system prompt 编排
- provider 选择
- 密钥管理
- 限额判定
- 请求日志写入
- 模型调用细节

---

## 3. 后端负责什么

后端作为 AI 网关和策略层，负责：

- 接收来自客户端的 AI 请求
- 识别设备身份
- 执行日限额和周限额
- 拼装 AI system prompt 配置
- 调用单一模型
- 把结果以流式方式返回给客户端
- 记录请求元数据
- 提供管理后台需要的配置读写接口

后端不负责：

- 存储正文内容
- 存储摘要内容
- 替用户管理文档
- 做多模型路由
- 做账号登录体系

---

## 4. 管理后台负责什么

管理后台只做单人运维所需的最小功能：

- 简单登录
- 当前密钥查看与更新
- 当前 AI system prompt 配置查看与更新
- 请求历史查询
- 请求状态和失败原因查看
- 设备限额查看
- 手动封禁设备

管理后台不做：

- 多角色权限
- 审批流
- 团队协作
- 复杂报表
- 多租户隔离界面

---

## 5. 轻量身份模型

V3 不做账号体系，但仍然需要一个设备维度的身份。

固定模型：

- 客户端首次启动生成 `installationId`
- `installationId` 本地持久化
- 后端在 `bootstrap` 时签发 `deviceToken`
- 客户端本地持久化 `deviceToken`
- 客户端调用后端时带上 `installationId`
- 客户端调用后端时带上 `deviceToken`
- 后端按 `installationId` 和 `deviceToken` 做限额和请求记录

这不是账号系统，只是一个匿名设备标识。

---

## 6. 在线请求流程

### 6.1 起稿 / 续写 / 编辑

1. 客户端采集当前正文和用户输入
2. 客户端发送请求到后端
3. 后端检查设备身份和限额
4. 后端加载当前 AI system prompt 配置
5. 后端组装模型输入
6. 后端调用单一模型
7. 后端流式返回正文增量
8. 后端返回最终 metadata
9. 客户端更新正文和侧栏状态

### 6.2 请求失败

如果出现以下情况，后端直接返回明确错误：

- 超出日限额
- 超出周限额
- 后端不可用
- provider 不可用
- 参数非法
- 认证失败

---

## 7. 离线请求流程

1. 客户端发现网络不可用
2. AI 入口阻断
3. UI 显示网络不可用
4. 正文编辑和本地保存继续可用

---

## 8. 数据流

### 8.1 本地保留

- 正文内容
- 本地文件名
- 最近打开列表
- 本地文档身份标记
- 版本历史

### 8.2 后端保留

- 请求元数据
- 设备维度限额统计
- AI system prompt 配置
- 密钥配置
- 错误码
- 耗时
- token 统计

### 8.3 后端不保留

- 正文原文
- 摘要原文
- 选区原文的长期副本
- AI system prompt 输入全文的长期副本

---

## 9. 存储约束

- 前端本地文件仍使用 Markdown
- 后端使用关系型数据库保存配置和请求元数据
- 日志系统保存短期历史查询所需的非敏感数据
- 敏感正文不进入日志和数据库

---

## 10. 不实现的扩展点

V3 不实现以下能力，代码中不要加入对应分支：

- 多模型适配器
- 多租户扩展
- 更细粒度的运营报表
- 更复杂的 AI system prompt 版本管理
- 云端文档同步
