# TASK_20260412_031.md

## 本轮目标
本轮只完成：在已经跑通 `start` / `continue` / `edit` 的后端写作链路上，新增一个**内存版 quota gate**，让三条写作路由共用同一套设备维度日限额和周限额判断，并且只对**已经接受**的请求计数。

---

## 本轮背景

- `task/TASK_20260411_027.md` 已经把 `Backend/` Swift + Vapor 骨架、`GET /v3/health`、`POST /v3/client/bootstrap` 和内存态 `deviceToken` 复用跑通。
- `task/TASK_20260411_028.md` 已经把 `POST /v3/writes/start` 跑通，并验证了 bootstrap-issued token 的校验、backend-only transport envelope 和 deterministic stub completion。
- `task/TASK_20260412_029.md` 已经把写作 transport envelope 做成 route-neutral，并把 `POST /v3/writes/continue` 接到了同一条 bootstrap-token 路径上。
- `task/TASK_20260412_030.md` 已经把 `POST /v3/writes/edit` 接到了同一条 bootstrap-token 路径上，并补了选区校验。
- 现在三条写作路由都已经存在，但后端还没有真正的限额判定；bootstrap 只是在响应里返回默认日/周限额摘要，实际的用量统计和拒绝逻辑还没落地。
- 这一张 task 只负责**内存版** quota gate，不做数据库、Redis、admin UI 或持久化请求日志。

## 本轮要做

- 在 `Backend/` 里新增一个**内存态** quota ledger / gate
- 让 `POST /v3/writes/start`、`POST /v3/writes/continue`、`POST /v3/writes/edit` 共用同一套 quota 判断
- quota 维度固定为设备维度，当前阶段按 `installationId` 记账
- quota 统计单位固定为 AI 请求次数
- 每次后端**接受**一条写作请求后，才把日用量和周用量各加 1
- 被后端拒绝的请求不计数
- 先完成设备 token / action / selection 等请求校验，再做 quota 判定和扣减，避免无效请求把额度吃掉
- 日限额和周限额都必须同时生效
- 日 / 周时间口径必须沿用 `docs/V3/DATA3.0.md` 里的规则：
  - 日统计使用 `Asia/Shanghai` 的自然日
  - 周统计使用 `Asia/Shanghai` 的周一日期
- 继续沿用当前默认阈值：
  - `dailyLimit = 50`
  - `weeklyLimit = 200`
- quota 超限时返回明确的 `quota_exceeded`，并使用 `HTTP 429 Too Many Requests`
- 只做进程内记账，后台重启后计数可以归零；这一阶段不要求持久化
- 补最小测试，覆盖：
  - 三条写作路由在额度内仍可通过
  - 日限额超出会拒绝
  - 周限额超出会拒绝
  - 被拒绝的请求不会推进计数

## 建议实现内容

以下不是唯一实现方式，但请保持目标一致：

- `Backend/Sources/VibeWriteBackend/Services/InMemoryQuotaLedger.swift`
- `Backend/Sources/VibeWriteBackend/Writes/WriteService.swift`
- `Backend/Sources/VibeWriteBackend/configure.swift`
- `Backend/Tests/VibeWriteBackendTests/QuotaGateTests.swift`
- quota gate 可以做成 `actor`，但必须保证单个请求的“检查 + 记账”是原子的
- quota gate 的时间判断必须以可测试的方式实现，最好允许注入当前时间或时钟，避免测试依赖真实时钟
- `WriteService` 里的 quota gate 调用点必须放在设备 token / action / 选区等请求校验之后、返回 stub completion 之前
- `quota_exceeded` 时直接返回 `429`，不要偷偷降级成别的错误类
- 三条写作路由共用同一个 ledger，不要分别记三份独立额度
- 目前只需要内存记账，不要提前为了后续数据库迁移把接口设计得过宽
- bootstrap 响应继续只返回默认限额摘要，不需要把实时用量回传给客户端
