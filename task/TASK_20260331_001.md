# TASK.md

## 本轮目标
本轮只完成：VibeWrite MVP 的 M1 页面骨架与视觉结构，使用 SwiftUI 实现 macOS 桌面应用的首页 / 工作台与写作项目页，并用 mock 数据搭出符合苹果原生体验的现代清爽高级视觉风格。

---

## 本轮要做
- 搭建 macOS SwiftUI 应用的基础页面结构与导航骨架
- 实现首页 / 工作台
- 实现写作项目页的两个状态骨架：讨论起稿态、正文协作态
- 拆分核心组件，保持结构清晰、可继续迭代
- 使用 mock 数据填充页面内容与空状态
- 做基础的响应式布局，保证桌面端观感和层级关系正确

---

## 本轮不要做
- 不接真实 AI
- 不做真实上下文维护
- 不做后端
- 不做本地持久化
- 不做语音输入
- 不做长篇管理、模板、作品集、社区、多端同步
- 不做复杂版本树
- 不做重型工具栏或企业后台式功能

---

## 本轮主流程
1. 先按照 PRD / IA / Wireframes 明确首页与写作项目页的骨架
2. 搭建 SwiftUI macOS app 的基础入口与页面容器
3. 实现首页：顶部栏、快速开始区、最近项目列表、灵感示例
4. 实现写作项目页：顶部栏、左侧对话协作区、右侧正文区、轻量上下文辅助区、版本回退区
5. 用 mock 数据把两个项目页状态完整填满
6. 统一视觉语言，调整为现代清爽、精致克制、原生 macOS 感
7. 做最小自测，确认结构、层级和页面气质符合文档要求

---

## 验收标准
- [ ] 首页包含“直接起稿”和“先讨论再起稿”两个入口
- [ ] 首页包含最近写作项目列表与少量灵感示例
- [ ] 写作项目页采用“左对话、右正文、轻量上下文区”的双栏结构
- [ ] 写作项目页包含讨论起稿态与正文协作态两种骨架
- [ ] 页面整体气质符合“现代清爽、高级精致、苹果原生应用体验”

---

## 实现要求
- 优先保守实现，不自行扩展需求
- 优先保证主流程闭环，不优先做附加功能
- 若遇到未定义需求，默认不实现
- 若发现需要大范围重构，先停止并说明
- 组件命名要清晰直接，方便后续继续做交互与上下文层
- UI 不要做成普通聊天软件，也不要做成重型写作工具后台
