## 本轮目标
本轮只完成：把前后端拆分后的默认 prompt 生成重新收口到旧版的语义和结构，不引入新的提示词内容，不改业务含义，只修复当前 current-route metadata prompt 与旧 builder 不一致的问题。

---

## 本轮背景

- 当前 V3 的 backend gateway 已经接管默认 AI 路径，但 review 发现 default current-route metadata prompt 仍然和拆分前的 `WritingAIPromptBuilder` 有明显差异。
- 现有差异主要集中在 metadata 的 system/user prompt 组织方式上，属于拆分后不必要的语义漂移，而不是拆分本身必须带来的变化。
- 这轮任务只处理默认路径的 prompt parity，不做 prompt 多版本管理，不做新的模型接入，不改 backend/admin 架构。

## 本轮要做

- 对照拆分前的 prompt builder 和当前 backend prompt composer，恢复默认 current-route metadata prompt 的旧版语义、结构和消息边界。
- 保留拆分后必须有的后端配置读取、shared DTO、路由分层和 provider 调用位置，不回退到客户端直连实现。
- 清理当前 prompt 中新增但不属于旧版语义的说明，避免默认 prompt 继续悄悄变宽或变死板。
- 补齐能证明默认 prompt 语义未漂移的验证。

---

## 本轮不要做

- 不做 prompt 多版本管理
- 不做新的模型接入
- 不做 backend/admin 的额外重构
- 不改变默认 runtime 的后端网关架构
- 不用测试脚本掩盖 prompt 语义偏差

---

## 本轮主流程

1. 对照拆分前的 `WritingAIPromptBuilder` 和当前 `BackendPromptComposer`，找出 default current-route metadata prompt 的语义差异。
2. 只收回拆分后多出来的提示词内容和边界变化，保持旧版的结构和含义。
3. 用 backend 测试或等价验证确认默认 prompt 输出和旧版语义对齐。
