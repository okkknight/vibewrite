# TASK.md

## 本轮目标
本轮只完成：VibeWrite MVP 的 M2 前端交互骨架。在不接真实 AI、不做后端和持久化的前提下，把 M1 的页面骨架升级为可演示的“和 AI 一起写”的主流程，包括起稿流转、正文自动更新、局部修改入口、基础回退入口和 AI 建议继续区。

---

## 本轮要做
- 完成首页两种起稿入口的完整流转
- 完成“直接起稿”后的 mock 起稿结果自动写入正文
- 完成“先讨论再起稿”的 mock 讨论到起稿流转
- 完成 mock 修改结果自动更新正文
- 保持正文可直接编辑
- 实现选区浮层的骨架和“选区带入对话”主路径
- 实现基础撤销 / 前后对比 / 本段重试入口
- 实现 AI 建议继续区的展示和基础交互骨架
- 保持页面结构、视觉气质和命名风格与 M1 一致

---

## 本轮不要做
- 不接真实 AI
- 不做真实 prompt 编排
- 不做真实项目上下文更新逻辑
- 不做后端
- 不做本地持久化以外的存储
- 不做复杂版本树
- 不做多文档管理
- 不做模板、作品集、社区、语音输入、多端同步
- 不把页面改成普通聊天产品或重型写作工具

---

## 本轮主流程
1. 先按照 PRD / IA / Wireframes 再确认 M2 的主交互范围
2. 梳理首页到写作项目页的状态流转
3. 实现“直接起稿”与“先讨论再起稿”的 mock 交互
4. 让 mock 的 AI 起稿和修改结果直接进入正文
5. 实现正文编辑、选区浮层和回退入口骨架
6. 实现 AI 建议继续区的展示
7. 做最小自测，确认主链路可演示、页面气质不跑偏

---

## 验收标准
- [ ] 用户可以从首页进入“直接起稿”流程
- [ ] 用户可以从首页进入“先讨论再起稿”流程
- [ ] mock 起稿结果会默认直接写入正文
- [ ] mock 修改结果会更新当前正文
- [ ] 用户可以直接编辑正文
- [ ] 用户选中文本后可以看到局部修改入口骨架
- [ ] 页面上可以看到“撤销 / 前后对比 / 本段重试”入口
- [ ] 页面上可以看到 AI 建议继续区，且不显得过重
- [ ] 页面整体仍然保持“极简写作协作器”的气质

---

## 实现要求
- 优先保守实现，不自行扩展需求
- 优先保证主流程闭环，不优先做附加功能
- 若遇到未定义需求，默认不实现
- 若发现需要大范围重构，先停止并说明
- 组件命名要清晰直接，方便后续继续做上下文层和真实 AI 接入
- UI 不要做成普通聊天软件，也不要做成重型写作工具后台
