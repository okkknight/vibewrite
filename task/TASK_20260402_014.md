# TASK_20260402_014.md

## 本轮目标
本轮进入 V2-M3：把编辑真正做成“局部 patch + 线性回退”，让用户在正文中心页面里进行选区修改、局部对比、撤销和重试时，感受到的是稳定的 patch 工作流，而不是整篇重写或新的版本管理系统。

这轮的重点不是扩更多 AI 能力，而是把现有的编辑主线补完整，尤其是：

- 选区编辑要尽量局部
- patch 应用期间要锁定目标文本，避免漂移
- 回退、对比、重试要依赖线性 revision history
- UI 上的 patch / 回退能力要按 `docs/V2/UI2.0.md` 和 `docs/V2/Wireframes2.0.md` 的层级来出现

当前代码已经有三动作主线和基础版本入口，但 M3 还需要把“局部修改是局部的”这件事真正做实，而不是只停留在按钮和历史记录上。

---

## 本轮背景

- task011 已经完成 V2-M1 的编辑器优先骨架。
- task012 已经清掉首页残留的 V1 讨论式 runtime 语义。
- task013 已经把正常 runtime 收束到 `startDraft -> continueWriting -> edit`。
- 现在的剩余问题不是主路径有没有，而是 `edit` 是否真的以 patch 级别工作，是否能在局部修改、回退、对比、重试时保持稳定。
- V2 的正式设计文档明确要求：
  - 局部编辑必须是真正局部
  - patch 期间应锁定目标文本
  - 版本回退是增强层，不是主舞台
  - 页面必须保持正文中心、安静、按需展开

### 这轮要统一的判断
- 选区编辑是不是在做真正的局部 patch
- patch 应用时目标文本是否会被并发编辑干扰
- undo / compare / retry 是否还只是“历史按钮”，还是已经形成线性回退闭环
- UI 上的局部修改、回退、对比是否仍然是正文周边增强层，而不是控制台化能力块

## 本轮要做

- 把 `edit` 变成真正的 patch 流程
  - 选区编辑优先走局部 patch，不要默认退化成全文重写
  - patch 结果应尽量只替换选区或局部片段
  - 如果现有实现里仍有全量替换逻辑，必须收进局部 patch 的应用流程里，而不是作为正常 runtime 常态

- 做好 patch 应用期间的锁定与回退
  - patch 生成 / 应用期间锁定目标文本，避免用户继续改动造成位置漂移
  - patch 成功后再解锁并刷新正文状态
  - patch 失败时不要污染正文内容、历史记录或当前选区状态
  - 重试上一轮修改时，要尽量复用上一条 revision 的目标信息，而不是重新发散成新的编辑意图

- 保持线性 revision history
  - 当前版本历史应当是线性可回退的，不要引入复杂版本树
  - 撤销、前后对比、本段重试都要围绕同一条线性历史运作
  - 版本记录里至少要能支撑回退、对比和重试这三件事

- 让局部 patch 与 UI 结构对齐
  - 选中文本时出现的浮层要对应 `edit` / patch 语义
  - 历史与版本抽屉继续保持可收缩、按需展开
  - 回退与对比入口要安静，但随手可用
  - 不要把 patch 交互做成重型编辑器工具箱

- 维持 V2 页面气质
  - 正文仍然是主视觉
  - AI、历史、版本仍然是辅助层
  - 不要因为补 patch 能力而把页面改回工作台感

- 真实验证页面效果
  - 改完后必须实际启动 app，验证选区 patch、撤销、对比、重试都能在正常 runtime 里顺手完成
  - 不能只跑单测
  - 要确认 patch 期间的锁定、回退后的正文状态和历史状态都符合 V2 设计

---

## 本轮不要做

- 不做新的版本树
- 不做复杂 patch 编辑器
- 不做 M4 的真实 AI 协议重构
- 不做新的模式分流
- 不做工作台式双栏主界面
- 不做模板中心、作品库、章节树、人物库
- 不把 `edit` 拆成更多显性主入口
- 不为了 patch 机制而重写首页骨架或三动作主线

1. 先阅读 `docs/V2/PRD2.0.md`、`docs/V2/IA2.0.md`、`docs/V2/UI2.0.md`、`docs/V2/Wireframes2.0.md`、`docs/V2/AGENTS.md`、`docs/V2/Milestones.md`，确认这轮必须围绕“局部 patch + 线性回退”收口。

3. 复述当前代码里的 revision history、selection edit、undo / compare / retry 入口，找出哪些只是“历史记录”，哪些是真正的 patch 机制。
4. 把选区编辑和局部修改改成更明确的 patch 流程，保证目标文本锁定、局部替换、失败回滚都可控。

8. 实际启动 app，确认选区 patch、回退和对比都能在真实窗口里工作，而且页面仍然像 V2 的正文中心编辑器，而不是控制台。
