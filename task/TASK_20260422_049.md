# TASK_20260422_049.md

## 本轮目标
本轮只完成：把 `continueWriting` 和 `edit` 从“全文上传 / 全文回传”的 backend gateway 协议重构为“窗口化请求 + patch 化响应”，直接切到新协议，不保留兼容层，同时保持当前产品语义和交互结果不变。

---

## 本轮背景

- `task/TASK_20260420_048.md` 已经查清 `continueWriting` 偶发 `HTTP 413 Payload Too Large` 的真实触发层，并且方案 A 已经把写作路由的 body 收集行为稳定住，但那只是把成功上界变成后端可控，并没有从协议层解决正文会随着写作持续变长的问题。
- 当前共享 DTO 和 backend gateway 协议仍然要求客户端把 `project.documentText` 作为全文上传到后端，而后端在 prose 路径和 metadata 路径里又把完整 `WritingAIResponse.documentText` 回给客户端，所以请求和响应体都会随正文增长而持续膨胀。
- 现有 `continueWriting` 的 backend prompt 实际只使用正文尾部窗口；现在 body 仍然很大，主要是因为协议层仍然上传全文并回传全文，而不是因为 LLM 真的需要整篇正文。
- 现有 `edit` 的 backend prompt 仍然把全文正文直接送进 prompt，后端最终替换选区时也依赖 `selectionRange` 在 `request.project.documentText` 全文上做 patch，所以它不能像 `continueWriting` 一样只靠“裁短 prompt”来解决，必须一起改协议和 patch 应用边界。
- 这轮人类决策已经明确：
  - `continueWriting` 和 `edit` 一起做方案 B
  - `continueWriting` 传“最后 1200 中文字左右”，优先按段落截取，最多不超过 1500
  - `edit` 采用“局部窗口优先，复杂场景回退”的策略
  - 直接切新协议，不做兼容升级
  - 返回 patch，而不是回传全文

## 本轮要做

- 把 `continueWriting` 请求改成只携带续写所需的稳定上下文，而不是整篇 `project.documentText`；尾部窗口默认按段落优先截取约 1200 中文字，硬上限不超过 1500。
- 把 `continueWriting` 响应改成 patch 语义，后端只返回 `appendedText`，由客户端基于本地锁定正文做最终拼接、保存和 revision 记录。
- 把 `edit` 请求改成局部窗口协议：只上传选区、选区前后局部上下文、必要的摘要/目标/风格信息，以及用于客户端本地应用 patch 的锁定信息；不再要求后端收到全文正文。
- 把 `edit` 响应改成 patch 语义，后端只返回 `replacementText`，由客户端在锁定正文上本地应用；对于复杂场景，允许在新协议内回退到更大的局部窗口或更宽的上下文，但不回退到旧的全文上传协议。
- 直接切换 shared contracts、app client、backend route model、executor、response builder 和相关测试到新协议，不保留旧字段兼容层，也不让旧协议继续可用。
- 补齐验证，证明 `continueWriting` 和 `edit` 在新协议下仍能保持当前产品语义，且请求/响应体不再随全文无限增长。

---

## 本轮不要做
- 不保留新旧两套 gateway 协议并行
- 不只是把 prompt 里的全文裁短，但协议和回包仍然维持全文语义
- 不改写当前产品动作语义，不把 `continueWriting` 变成聊天补全，不把 `edit` 变成全文重写
- 不重做 metadata 产品逻辑，只允许为了适配 patch 协议调整它所依赖的输入边界
- 不扩大到新的模型接入、压缩算法、分块存储或文档持久化架构重构

---

## 本轮主流程
1. 先盘清当前 `continueWriting` / `edit` 的请求链、prompt 使用链、patch 应用链，明确哪些地方默认假设了“上传全文 / 回传全文”。
2. 设计并落地新的 shared contracts：为 `continueWriting` 定义 tail-window 请求和 `appendedText` 响应，为 `edit` 定义 local-window 请求和 `replacementText` 响应，并移除旧全文语义字段。
3. 同步重构 app flow 和 backend 执行路径，让客户端基于本地锁与 patch 响应完成最终全文应用、流式预览、保存和 revision 记录。
4. 增加最小但足够强的测试，证明 `continueWriting` 与 `edit` 在新协议下可工作、复杂编辑场景能走局部回退策略、并且 gateway payload 不再按全文线性膨胀，然后把结果写回 handoff / context。
