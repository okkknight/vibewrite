# TASK_20260412_034.md

## 本轮目标
本轮只完成：在已经有可查询内存读模型的 request log 基础上，补上**最小后台访问面**，也就是简单登录 / 登出 + 请求列表查询接口，让后续管理页可以直接读取真实后台数据，而不是再绕一层临时调试接口。

- 现在 backend 里已经能查请求日志，但还没有后台登录态，也没有任何 HTTP admin 路由。
- 这一张 task 只负责**最小后台访问面**，不做 secrets、prompt、quota 或 device 管理页面。

## 本轮要做

- 在 `Backend/` 里新增一个最小的后台登录态实现
- 登录只面向单个管理员，不做账号体系、角色权限或邀请机制
- 登录 / 登出接口固定为：
  - `POST /v3/admin/login`
  - `POST /v3/admin/logout`
- 登录请求字段固定为：
  - `username`
  - `password`
- 登录成功后必须设置名为 `vibewrite_admin_session` 的 session cookie
- 这个 cookie 只用于后台登录态，不承载客户端身份
- session 先做内存态即可，重启后失效可以接受
- 读取请求日志的后台接口固定为：
  - `GET /v3/admin/requests`
- `GET /v3/admin/requests` 必须受后台 session cookie 保护
- 请求列表必须直接复用 `task/TASK_20260412_033.md` 里已经做好的 request log query / summary 能力，不要重写一套查询逻辑
- `GET /v3/admin/requests` 支持的查询条件固定为：
  - `installationId`
  - `action`
  - `status`
  - `errorCode`
  - `createdAtStart`
  - `createdAtEnd`
- 其中 `installationId` 就是客户端 bootstrap 使用的安装 ID，也是当前后台语境里的设备 ID
- 返回结果必须包含：
  - `entries`
  - `summary`
- `summary` 至少包含：
  - `totalCount`
  - `acceptedCount`
  - `rejectedCount`
- 查询结果继续按时间倒序返回
- 结果里只允许出现请求元数据，不允许出现正文、摘要、`project.prompt`、`userMessage`、`selectionText` 或 AI system prompt 原文
- 这一张 task 只做请求列表查询，不做 secrets、system-prompt、quota、devices 或 dashboard
- 补最小测试，覆盖：
  - 登录成功会设置 session cookie
  - 错误凭证登录失败
  - 未登录访问 `GET /v3/admin/requests` 被拒绝
  - 登录后可以按过滤条件查询请求日志
  - 登录后可以拿到 summary
  - 登出后 session 失效
