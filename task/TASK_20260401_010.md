# TASK_20260401_010.md

## 本轮目标
本轮只完成一件事：把 VibeWrite 整理成适合产品验证的“干净启动态”。

这里的“干净”不是只删一个 JSON 文件，而是要把当前项目里所有会干扰验证的历史数据源、默认样板数据、首启种子数据一起收口，确保你在桌面打开 app 时看到的是可控、可解释、可重置的状态，而不是一堆历史项目和示例内容混在一起。

---

## 本轮背景

- 现在 app 的本地持久化里已经积累了很多历史项目，主要落在 `~/Library/Application Support/VibeWrite/local-project-store.json`。
- 这个 store 里会保存：
  - 项目列表
  - 最近打开的项目
  - 正文内容
  - 对话内容
  - 项目上下文
  - revision history
- 当本地 store 不存在时，当前实现会自动种 3 个默认示例项目，所以“删掉文件”并不等于“得到空白验证环境”。
- 首页和写作页里还散落着多处默认样板：
  - 首页输入框的默认文案
  - 灵感示例列表
  - `WorkspaceFixtures.bootstrapProjects(...)` 的种子项目
  - `WritingProject.quickStart(...)` 里的示例正文和示例对话
  - `MockWritingEngine` 的固定示例回复
- 这些内容在开发和演示时有帮助，但对产品验证来说会制造干扰，容易让人误以为是用户真实内容或历史数据。

### 需要先统一的判断
- 哪些内容属于“用户真实历史数据”
- 哪些内容属于“启动时默认样板”
- 哪些内容只应该留在测试、Preview 或显式 Demo 模式里
- 启动时是否应该允许“无数据、无示例”的空白状态

---

## 本轮要做

- 梳理并收口历史数据来源
  - 明确本地项目 store 的真实位置和结构
  - 给出一个可靠的清理或重置路径，不只是手动删文件
  - 确保用户能回到空白验证状态

- 去掉或隔离默认样板数据
  - 不要让首启自动把 3 个示例项目塞进正式验证环境
  - 不要让首页默认输入框和灵感示例继续污染验证
  - 如果还需要示例内容，只能放到测试、Preview、或明确的 demo/seed 开关里

- 保留正常功能闭环
  - 空白启动后仍然能新建项目、进入起稿/讨论流程
  - 现有 AI 流程、项目页、回退、重命名、删除等功能不能被这次清理破坏
  - UI tests 和 unit tests 仍然要能用独立的临时 store 跑

- 给出明确的清理方式
  - 最好能支持一键重置本地数据到空白状态
  - 如果实现上不适合按钮，也至少要提供一个稳定、可复用的 reset 入口或辅助方法
  - 清理后的状态必须是可重复、可验证的，不要靠人工删改文件碰运气

---

## 本轮不要做

- 不做新的云端同步
- 不做账号系统
- 不做复杂的数据迁移体系
- 不做大范围 UI 重构
- 不重做写作流程本身
- 不增加新的产品功能入口，只为清理数据而堆更多界面
- 不把测试专用的 seed 数据误删到影响现有自动化测试

---

## 本轮主流程

1. 先把当前所有历史数据和默认数据来源列清楚，确认哪些是持久化数据，哪些是代码种子。
2. 决定正式产品验证环境应该如何启动：空白启动、保留最近项目、还是可显式重置。
3. 为本地 store 增加可靠的清理/重置能力，确保能恢复到干净状态。
4. 去掉首启自动种示例项目的行为，或者把它严格限制在 Preview / Demo / Test 场景。
5. 清理首页和项目页上用于“示例展示”的默认文案与示例列表，避免它们继续污染验证。
6. 补最小测试，验证空白启动、重置后状态、以及测试环境不会被这次清理影响。
7. 运行 `swift test` 和 `xcodebuild test -project VibeWrite.xcodeproj -scheme VibeWrite -destination 'platform=macOS'` 确认没有回归。

  - 如果还要保留示例数据，请把它们放进显式的 demo / preview 开关里，而不是首启默认行为

- `Sources/VibeWriteApp/Shared/Models/VibeWriteModels.swift`
  - 处理 `WorkspaceFixtures.bootstrapProjects(...)` 的去向
  - 处理 `WorkspaceFixtures.inspirationPrompts`
  - 检查 `WritingProject.quickStart(...)`、`entryShell(...)`、`defaultTitle` 是否仍然在正式产品路径里注入过多默认内容
  - 让示例正文、示例对话、示例灵感只在需要的场景中出现

- `Sources/VibeWriteApp/Features/Home/HomeView.swift`
  - 去掉会干扰验证的默认输入内容
  - 如果保留 prompt 输入框，请改成更中性的空白占位，不要继续预填“成年人孤独感 / 雨夜重逢”这种示例

- `Sources/VibeWriteApp/App/RootShellView.swift`
  - 如果需要一个显式的“清空本地数据”入口，可从这里或上层导航暴露一个最小、低风险的动作

- `Tests/VibeWriteAppTests/`
  - 新增/更新测试，覆盖以下场景：
    - 新启动或重置后得到空白 store
    - 不会因为缺失 store 自动种 3 个示例项目
    - 验证环境仍可通过注入的临时 store 正常跑测试
