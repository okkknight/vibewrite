# TASK.md

## 本轮目标
本轮只完成一件事：把 VibeWrite 的 MiniMax 接入方式改成和隔壁 `kaichang` 项目一致的 Anthropic-compatible 方案，避免继续用当前这条 OpenAI-compatible `chat/completions` 路径去打 MiniMax。

这不是“换一个模型 id”就结束的任务。本轮要把**接口协议、base URL、认证方式、模型默认值、错误映射、测试覆盖**一起对齐，确保同一把可用的 MiniMax key 在 VibeWrite 里也能正常返回。

---

## 本轮背景

- 现在 VibeWrite 的真实 AI client 走的是：
  - `https://api.minimax.io/v1/chat/completions`
  - `Authorization: Bearer <key>`
  - 自己手写的 OpenAI-compatible 请求 / 响应解析
- 我已经独立验证过：
  - 同一把 key 在当前 VibeWrite 路径上会返回 `401 Unauthorized`
  - 同一把 key 在隔壁 `kaichang` 的 MiniMax 接法上是通的
- `kaichang` 的实现显示：
  - MiniMax provider 走 Anthropic-compatible 接口
  - 默认 base URL 是 `https://api.minimaxi.com/anthropic`
  - 通过 Anthropic SDK / Anthropic 风格 messages 请求访问
- 进一步实测结果也表明：
  - `MiniMax-M2.5-highspeed` 和 `MiniMax-M2.7` 在 Anthropic-compatible endpoint 上是可用的
  - 所以当前问题大概率不是单纯的 model id 写错，而是**接入协议不对**

### 当前要纠正的认知
- 不是把 `MiniMax-M2.7` 改成另一个名字就能解决
- 不是把原始 `401` 文案换掉就能解决
- 不是继续在 `v1/chat/completions` 上调参数就能解决
- 要把 VibeWrite 的 MiniMax client 调整成真正可用的 Anthropic-compatible 接法

---

## 本轮要做

- 把 VibeWrite 的 MiniMax client 改成 Anthropic-compatible 接口
  - 不再使用当前手写的 OpenAI-compatible `chat/completions` 请求
  - 统一改成和 `kaichang` 一样的 messages 流程
  - base URL、路径和请求体结构要对齐 MiniMax 的 Anthropic 兼容端

- 对齐认证方式
  - 按 Anthropic-compatible 方式发送请求
  - 不要继续假定 `Authorization: Bearer` 是唯一正确方式
  - 保留对 `MINIMAX_API_KEY` 的读取，但要让它进入正确的鉴权层

- 对齐默认模型与配置
  - 检查并修正默认模型名
  - 参考隔壁项目里已经验证可用的模型选择
  - 不要继续把当前项目默认值写死在一个未验证可用的组合上

- 修正错误映射
  - 401 / 403 / 2049 / “invalid api key” 仍然要映射成友好配置错误
  - 其它网络或服务错误保持原有降级语义
  - 不要把底层协议切换后新增的 raw error 直接暴露给 UI

- 补充最小测试
  - 覆盖 Anthropic-compatible 请求构建
  - 覆盖模型默认值 / 配置读取
  - 覆盖同一把 key 在新 client 下可正常返回的解析路径
  - 覆盖 invalid key 仍能被映射成产品级错误

## 本轮主流程

1. 先复述当前 VibeWrite 的 MiniMax 调用链和隔壁 `kaichang` 的调用链差异。
2. 确认 Anthropic-compatible 方案需要的 base URL、认证和消息结构。
3. 修改 `RemoteWritingAIClient` 或等价 client，让请求走正确协议。
4. 调整配置默认值，确保模型名和 endpoint 与真实可用组合一致。
5. 保留并完善 invalid key 的友好错误映射。
6. 补测试，验证新 client 在本地与 UI 流程里都可用。
7. 跑 `swift test` 和 `xcodebuild test -project VibeWrite.xcodeproj -scheme VibeWrite -destination 'platform=macOS'`，确认没有回归。
