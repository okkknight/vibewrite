# TASK_20260402_021.md

## 本轮目标
本轮只完成一件事：把底部输入区、动作语义和选区浮层严格对齐到文档要求，拆掉“AI 面板里的输入框”这种收敛写法。

这轮要完成的是一个真正的底部协作输入区：

- 它是独立 composer 或轻量底部工具区
- 它不是 AI 侧栏的一部分
- 它承载 startDraft / continueWriting / edit 三类动作
- 它和选区浮层联动
- 它保持 Typora 式白纸视觉基底下的低存在感

如果完成后输入框仍然藏在 AI 折叠区里，或者动作语义还在乱跳，那就不算通过。

## 本轮要做

- 建立独立输入区
  - 输入区应位于正文下方或底部工具区
  - 它必须和正文主线直接相连
  - 它不应嵌在 AI 侧栏中
  - 它应保持非常轻的视觉存在感

- 严格承载三类动作
  - `startDraft`
  - `continueWriting`
  - `edit`
  - 输入区上的语义、按钮、占位提示都必须围绕这三类动作组织
  - 不要再扩展出扩写、缩写、润色等独立按钮墙

- 让选区浮层回到上下文动作
  - 选区浮层必须更轻、更近、更短
  - 浮层动作应与 `edit / continueWriting` 有明确映射
  - 浮层不能撑成小工具箱
  - 浮层不能抢正文阅读

- 保持 patch 与 streaming 语义不变
  - 任务15 的真 patch 语义必须继续成立
  - 任务16 的流式正文必须继续成立
  - 本轮只改输入与动作承载方式，不改 patch 算法和 streaming 语义

- 保持 Typora 白纸体验
  - 输入区要轻
  - 浮层要轻
  - 不要用重卡片、厚边框或高对比控制件去包裹输入区
