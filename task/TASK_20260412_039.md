# TASK_20260412_039.md

## 本轮目标
本轮只完成：把后台管理 API 补齐到能直接支撑单人管理页的程度，新增总览、限额和设备管理能力，让现有内存态 device / quota / request 数据能够被后台查看、调整和封禁。  
这一轮不做后台网页 UI，不做数据库，不做 Redis，不做账号体系，不做多模型。

---

## 本轮背景

- `task/TASK_20260412_034.md` 已经把后台登录 / 登出和 `GET /v3/admin/requests` 跑通了。
- `task/TASK_20260412_035.md` 已经把 provider API key 和 admin 凭证收进同一份 secret config store，并支持 `GET/PUT /v3/admin/secrets`。
- `task/TASK_20260412_036.md` 已经把当前 AI system prompt 配置收进同一份 config store，并支持 `GET/PUT /v3/admin/system-prompt`。
- `task/TASK_20260412_037.md` 已经把 backend 写作路径切到了真实的后端 AI 执行链路。
- `task/TASK_20260412_038.md` 已经把客户端默认运行时切到了 backend gateway。
- 现在 backend 里仍然是内存态的 `InMemoryDeviceRegistry`、`InMemoryQuotaLedger` 和 `InMemoryRequestLogStore`，它们能支撑写作请求链路，但还没有完整的后台管理读写面。
- `docs/V3/ADMIN3.0.md` 里要求后台能看请求、改密钥、改 AI system prompt、看和改限额、查看和封禁设备；这一轮只补齐其中后台管理 API 所需的后端部分，不做网页 UI。

---

## 本轮要做

- 新增后台总览接口，基于现有内存态数据返回：
  - 今日请求数
  - 今日成功率
  - 今日超限数
  - 当前活跃设备数
  - 当前 provider
  - 当前 model
  - 当前日限额
  - 当前周限额
- 新增后台限额管理接口：
  - `GET /v3/admin/quota`
  - `PUT /v3/admin/quota`
  - 能查看当前日 / 周限额与当前已用量
  - 能直接更新当前日 / 周限额
  - 更新后必须立即影响 bootstrap 返回和写作请求的限额判定
- 新增后台设备管理接口：
  - `GET /v3/admin/devices`
  - `POST /v3/admin/devices/{installationId}/block`
  - `POST /v3/admin/devices/{installationId}/unblock`
  - 设备列表至少要能看到状态、首次出现时间、最近出现时间、token 签发时间、今日用量、周用量、封禁时间和封禁原因
  - 封禁和解封必须立即影响后续 bootstrap / 写作请求的校验结果
- 把 bootstrap 和写作链路接到当前设备状态和当前限额配置上：
  - blocked 设备不能继续正常写作
  - 当前限额更新后，bootstrap 返回的 quotaSummary 也要跟着更新
- 保持现有管理员 session 认证不变，后台新接口仍然只允许已登录管理员访问

## 验收标准

- [ ] `GET /v3/admin/overview` 能返回当前请求数、成功率、超限数、活跃设备数、provider、model、日限额和周限额
- [ ] `GET /v3/admin/quota` 能返回当前限额与已用量，`PUT /v3/admin/quota` 能更新当前限额
- [ ] `GET /v3/admin/devices` 能返回设备列表及其状态、用量、封禁信息
- [ ] `POST /v3/admin/devices/{installationId}/block` 和 `.../unblock` 能立即改变设备状态
- [ ] 被封禁的设备会在后续写作请求里被拒绝，错误类是 `device_blocked`
- [ ] 更新后的 quota 会立刻反映到 bootstrap 响应和写作请求的校验结果里
- [ ] 所有新后台接口仍然需要管理员 session cookie
- [ ] 没有引入数据库、Redis、后台网页 UI、RBAC、SSE、账号体系或多模型改造
