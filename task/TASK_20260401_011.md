# TASK_20260401_011.md

## 本轮目标
本轮只完成一件事：把 VibeWrite 的主界面收束成 V2-M1 的“编辑器优先”页面骨架。

具体来说，这一轮要把产品从当前更偏“工作台 / 双栏协作面板”的形态，调整成“安静的白纸 / 极简笔记本 / 正文优先”的形态：

- 首页只保留单一直接起稿入口和最近会话回流
- 写作会话页以正文编辑区为视觉中心
- AI、历史、版本等能力收进可收缩的辅助层
- 不再把“先讨论再起稿”作为首页主入口
- 不改 AI 协议、不改 patch 机制、不做 V2-M2 / M3 / M4 的能力实现

这轮的目标不是把所有功能补齐，而是先把页面骨架和信息层级摆正，让后续的动作模型、局部 patch、真实 AI 接入都建立在正确的 UI 基础上。

---

## 本轮背景

- VibeWrite 的 V2 设计已经完成，正式 source of truth 已迁移到 `docs/V2/`。
- 当前 V2 的正式 UI 方向是：
  - 页面首先像一张安静的白纸
  - 正文是唯一主舞台
  - AI / 历史 / 版本是正文周边的增强层
  - 页面默认安静，按需展开
- `docs/V2/Milestones.md` 里的 M1 明确要求：
  - 首页改成单一直接起稿页
  - 写作会话页改成正文中心结构
  - AI / 历史 / 版本都改为可收缩辅助层
  - 顶部栏只保留最轻入口
  - 空状态接近一张白纸
- 目前代码里仍然存在明显的 V1 形态：
  - 首页仍有“直接起稿”和“先讨论再起稿”两个主卡片
  - 写作页仍是左对话、右正文的固定双栏工作台感布局
  - 选区、建议继续、版本与回退等内容仍以较重的分区方式出现

### 需要先统一的判断
- 首页的主入口应不应该只保留一个
- “先讨论再起稿”是否继续作为正常 runtime 的首页主入口
- 写作页是继续保留固定双栏，还是改成正文中心 + 辅助层
- 哪些能力应该默认收起，哪些应该显性展示
- 哪些旧版能力只作为历史兼容或 demo / test 场景保留

---

## 本轮要做

- 重构首页为单一直接起稿页
  - 首页只保留一个主起稿入口
  - 直接起稿应成为唯一显眼入口
  - 最近会话保留为回流入口
  - 默认占位文案必须中性、空白，不要再预填示例内容
  - 正常 runtime 不要继续展示“先讨论再起稿”主卡片

- 重构写作会话页为编辑器优先骨架
  - 中央必须是正文编辑区
  - AI、历史、版本改成可收缩辅助层
  - 顶部栏只保留最轻状态与入口
  - 页面整体气质要更像文本编辑器，而不是工作台

- 保留必要的核心协作闭环
  - 用户仍然可以从首页进入新会话
  - 用户仍然可以打开最近会话继续写
  - 用户仍然可以看到正文、编辑正文、回到首页
  - 现有本地存储、回退、AI 流程不要因为这次 UI 调整被破坏

- 控制本轮的改动边界
  - 不改 AI 请求协议
  - 不改响应 JSON 契约
  - 不改局部 patch 机制
  - 不改本地项目存储结构
  - 不做多模型路由
  - 不做账号系统

---

## 本轮不要做

- 不做 V2-M2 的动作模型重构
- 不做 V2-M3 的局部 patch 机制实现
- 不做 V2-M4 的真实 AI 接入重构
- 不做新的设置页
- 不做复杂版本树
- 不做工作台式多入口模式墙
- 不做模板中心、作品库、章节树、人物库
- 不把首页重新做回“两个起稿模式并列的大卡片墙”
- 不在正常 runtime 继续显式暴露“先讨论再起稿”主入口
- 不把写作页继续维持成左对话右正文的等权双栏工作台
- 不因为这轮 UI 收敛而删除 test / demo 需要的最小兼容路径

## 本轮主流程

1. 先阅读 `docs/V2/PRD2.0.md`、`docs/V2/IA2.0.md`、`docs/V2/UI2.0.md`、`docs/V2/Wireframes2.0.md`、`docs/V2/AGENTS.md`、`docs/V2/Milestones.md`，确认 M1 的目标就是“编辑器优先的页面骨架”。
2. 复述当前首页和写作页的实际代码结构，确认哪些区域是主视觉，哪些区域是辅助层。
3. 重构首页为单一直接起稿页，去掉正常 runtime 的“先讨论再起稿”主卡片，只保留直接起稿和最近会话。
4. 重构写作会话页为正文中心结构，把 AI / 历史 / 版本收进可收缩的辅助层，避免固定双栏工作台感。
5. 调整顶部栏、空状态、占位文案、按钮布局与组件拆分，让页面整体气质变成“安静的编辑器”。
6. 更新或补充最小测试，确保新的首页与会话页骨架可用，核心流转不回归。
7. 运行 `swift test` 和 `xcodebuild test -project VibeWrite.xcodeproj -scheme VibeWrite -destination 'platform=macOS'`，确认改动没有破坏当前可验证链路。

以下不是唯一实现方式，但请保持目标一致，并尽量在这些文件里收口改动：

  - 将页面改造成正文优先的单主舞台结构
  - 把当前左对话 / 右正文的固定双栏布局，改成中央正文 + 可收缩辅助层
  - AI / 历史 / 版本应以折叠面板、抽屉、侧栏或轻量浮层出现
  - 顶部栏只保留最轻入口
  - 选区浮层可以保留，但不要让它演变成重型工具面板
  - 如果保留“建议继续”或“版本与回退”区域，也要让它们看起来是辅助层而不是第二主屏

- `Sources/VibeWriteApp/App/RootShellView.swift`
  - 根据新的页面骨架调整整体容器和过渡
  - 不要让根壳层继续强化“工作台式双栏”的视觉印象

- `Sources/VibeWriteApp/App/VibeWriteAppFlow.swift`
  - 仅在需要首页 / 会话页切换语义时做最小配合
  - 不要在这轮引入新的产品状态机
  - 不要改 AI 的请求 / 响应编排

- `Sources/VibeWriteApp/Shared/Theme/`
  - 如有必要，只做少量布局 / 间距 / surface 级别的视觉收敛
  - 不要把这轮变成一次完整重做主题系统的任务

- `Tests/VibeWriteAppTests/`
  - 更新首页和会话页相关测试，使其符合新的单入口首页和正文中心布局

### 设计自由度
- 首页里“直接起稿”卡片的具体视觉形式，可以由 coder 在白纸感约束下自行选择
- 会话页里 AI / 历史 / 版本辅助层的具体展开方式，可以由 coder 选择更自然的折叠 / 抽屉 / 侧栏方案
- 只要最终满足“正文优先、辅助层低存在感、页面不打扰写作”，实现细节可以让 coder 发挥
