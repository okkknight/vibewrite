## 本轮要做

- 在 `Backend/` 里新增一个内存版 AI system prompt config store
- 这份 store 只维护当前生效的一份配置，不做多版本管理，不做草稿 / 发布流 / 回滚树
- 这份 store 的内部记录固定视为 `current`
- `GET /v3/admin/system-prompt` 必须受现有后台 session cookie 保护
- `GET /v3/admin/system-prompt` 返回当前配置的完整可读内容，固定字段为：
  - `templateBody`
  - `actionRulesJson`
  - `modelContextRulesJson`
  - `updatedAt`
- `PUT /v3/admin/system-prompt` 必须受现有后台 session cookie 保护
- `PUT /v3/admin/system-prompt` 接受的字段固定为：
  - `templateBody`
  - `actionRulesJson`
  - `modelContextRulesJson`
- 这三个字段都可以单独更新；未传入的字段保持原值不变
- `actionRulesJson` 和 `modelContextRulesJson` 在请求里作为字符串传输，但内容必须是合法 JSON 文本；无效 JSON 直接返回 400
- `templateBody` 保存当前 system prompt 的共享基础提示词正文
- `actionRulesJson` 保存按 action 区分的提示词规则
- `modelContextRulesJson` 保存 provider / model / metadata route 相关的提示词规则
- 初始值必须从当前客户端的 `Sources/VibeWriteApp/Shared/AI/WritingAIPromptBuilder.swift` seed，尽量保留当前行为中的共享基础提示词、按 action 的规则和 provider/model 相关规则
- 这一步不要修改 `POST /v3/writes/start`、`POST /v3/writes/continue`、`POST /v3/writes/edit` 的外部行为
- 这一步不要把前端 prompt builder 删掉，也不要直接切换客户端请求路径
- 补最小测试，覆盖：
  - 未登录访问 `GET /v3/admin/system-prompt` 被拒绝
  - 登录后可以读取当前 system prompt snapshot
  - 登录后可以更新 `templateBody`
  - 登录后可以更新 `actionRulesJson`
  - 登录后可以更新 `modelContextRulesJson`
  - 更新后再次读取能看到新值
  - `actionRulesJson` / `modelContextRulesJson` 的无效 JSON 被拒绝
