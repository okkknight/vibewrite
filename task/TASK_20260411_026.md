# TASK_20260411_026.md

## 本轮目标
本轮只完成：把当前 app target 里的纯共享模型和 AI contract 提升成独立的 `VibeWriteShared` Swift target，供未来 backend target 和客户端共同引用。

---

## 本轮背景

- `task/TASK_20260411_025.md` 已经把 AI contract 从混杂实现里单独拎出来，但它仍然停留在 app target 语境内。
- 当前 `Package.swift` 只有 `VibeWriteApp` executable target 和测试 target，没有可独立复用的共享 library target。
- `Sources/VibeWriteApp/Shared/Models/VibeWriteModels.swift` 里仍然混着两类内容：
  - 纯共享数据类型：`ProjectContext`、`WritingTextSelectionRange`、`ConversationMessage`、`MessageRole`、`WritingProjectMode`
  - app 专属逻辑：`WritingProject`、fixture、revision、保存和恢复相关实现
- `Sources/VibeWriteApp/Shared/AI/WritingAIContracts.swift` 已有 AI contract 类型，但还没有真正进入一个独立模块边界。
- 后续 Phase 1 的后端 AI 网关需要直接依赖这些纯共享类型，不应该再反向依赖 app target。
- 这一步只建立共享模块边界，不做后端服务，不做 prompt / stream / provider 逻辑改动。

## 本轮要做

- 新建 `VibeWriteShared` Swift target
- 把纯共享模型和 AI contract 移到 `VibeWriteShared`
- 让 app target 改为依赖 `VibeWriteShared`
- 保持现有字段、编码格式、枚举 case、数据语义和运行行为不变

---

## 本轮不要做
- 不做 backend service
- 不做 provider 接入
- 不改 prompt 设计
- 不改流式体验
- 不改 `WritingProject` 的业务行为
- 不改本地文档、保存、另存为、最近打开
- 不做账号体系、权限、限额、日志设计
- 不把 decoder / helper / default implementation 一起搬进共享 target
- 不引入新的 AI system 语义

---

## 本轮主流程
1. 先确认当前 `Package.swift`、`VibeWrite.xcodeproj` 和 `Sources/VibeWriteApp/Shared/**` 的真实依赖关系，明确共享 target 需要被哪两个构建入口同时引用。
2. 创建 `VibeWriteShared` target，并把纯共享模型和 AI contract 文件放到新 target。
3. 更新 app target、xcodeproj 和 package 依赖，让现有代码从新 module 导入这些类型。
4. 跑 `swift test` 和 `xcodebuild build -project VibeWrite.xcodeproj -scheme VibeWrite -destination 'platform=macOS'`，确认改动只是模块边界变化。
