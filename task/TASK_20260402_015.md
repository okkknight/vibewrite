# TASK_20260402_015.md

## 本轮目标
本轮只解决一件事：把 V2-M3 的局部编辑做成“真 patch”，禁止继续用整篇 `response.documentText` 覆盖正文来冒充局部修改。

这轮不是再做一套新的编辑系统，而是把已经存在的 patch / lock / revision 模型真正接到正文应用路径上，让编辑结果只替换该替换的片段，其余内容保持不变。

### 这轮必须达到的效果
- 选区编辑只能修改选区及其必要的局部上下文
- 继续写可以追加新的正文段落，但不能偷偷把整篇正文重写成另一篇
- patch 失败、锁失配、选区丢失时，正文不能被污染
- 版本历史记录的是 patch 结果，不是“全文覆盖后再回推一个 patch 名字”

当前任务014 已经暴露出一个明确问题：

- `WritingEditPatch` 和 `WritingEditLock` 已经存在
- 但当前编辑流程仍然先把 `response.documentText` 整篇写回正文
- patch 只是随后从 before/after 反推记录

这轮 task015 的目标，就是把这个问题彻底修掉。

## 本轮背景

- task011 已经完成 V2-M1 的编辑器优先骨架。
- task012 已经清掉首页残留的 V1 讨论式 runtime 语义。
- task013 已经把正常 runtime 收束到 `startDraft -> continueWriting -> edit`。

- V2 文档对局部编辑的要求很明确：
  - 编辑必须是真正局部
  - patch 期间要锁定目标文本
  - 返回 patch，而不是整篇文章，是关键能力
  - 版本回退是辅助层，不是控制台化版本树

### 这轮要统一的判断
- 正文是不是通过局部 patch 应用，而不是整篇替换
- patch lock 是否真的保护了选区和正文
- 版本历史是否记录了局部变更，而不是整篇替换后的结果摘要
- 测试是否真的能防止“看起来像 patch，实际上还是全文覆盖”的实现回归

## 本轮要做

- 让正文应用路径变成真 patch
  - 不允许在正常 runtime 中把 `response.documentText` 直接赋给正文作为最终写入方式
  - 编辑结果必须通过 patch 结构应用到现有正文
  - 对选区编辑，优先只替换选中的局部片段
  - 对续写，只允许在正文尾部追加必要内容，不能重写整个文档

- 把 patch 与 lock 真正接到执行路径上
  - `WritingEditLock` 必须参与编辑开始、编辑中、编辑完成和失败恢复
  - 当锁定的正文和当前正文不一致时，要拒绝 patch 或显式回退，而不是静默覆盖
  - 锁失配时不能继续推进保存
  - patch 应用完成后再解锁、刷新正文和历史

- 让历史记录真正反映 patch
  - `WritingEditPatch` 应该描述实际应用的局部变更
  - revision history 里保存的 patch 必须与正文中的局部替换一致
  - 回退、对比、重试仍然维持线性历史，不引入版本树

- 强化测试，堵住“全文覆盖冒充 patch”
  - 必须新增或修改测试，明确断言：
    - 选区前缀不变
    - 选区后缀不变
    - 只有目标片段被替换
    - 如果锁失配，正文不发生变化
  - 不能只断言“结果里出现了某些新句子”
  - 不能只断言 revisionHistory 有记录

- 保持 V2 页面气质
  - 正文仍然是主视觉
  - AI、历史、版本仍然是辅助层
  - 不要把补 patch 这件事做成一个新的编辑器工具箱

- 真实验证页面效果
  - 改完后必须实际启动 app
  - 要确认选区 patch、续写、回退、重试都在真实窗口里工作
  - 不能只跑单测，也不能只看日志

- 不允许用“记录了 patch 历史”来替代“真的应用了 patch”
