# TASK.md

## 本轮目标
本轮只完成：为 VibeWrite 的 M2 交互骨架补齐 UI 自动化测试所需的改动，包括关键控件的稳定标识、必要的可测试性调整，以及最小可运行的自动化测试基础设施。目标是让后续 QA 可以不靠截图和坐标猜测，而是通过稳定的 accessibility identifier 和自动化测试入口来验收首页与写作项目页主流程。

---

## 本轮要做
- 为首页和写作项目页的关键交互控件添加稳定的 `accessibilityIdentifier`
- 确保首页两种起稿入口、最近项目入口、返回入口、正文编辑区、发送按钮、回退入口等都可以被 UI 自动化稳定定位
- 为关键视图补足可读性更高的无障碍信息，避免元素名称缺失或层级不稳定
- 如有必要，补充轻量的可测试状态入口，方便自动化测试验证起稿、切页、回退等流程
- 新增或完善最小自动化测试基础设施，使后续可以直接跑 UI 自动化验证
- 保持现有产品气质、页面结构和交互意图不变

---

## 本轮不要做
- 不接真实 AI
- 不做后端
- 不做真实项目上下文持久化
- 不做复杂版本树
- 不做多文档管理
- 不做模板、作品集、社区、语音输入、多端同步
- 不重构整体产品结构
- 不为了测试而大改视觉或交互

---

## 本轮主流程
1. 盘点 M2 里需要被 UI 自动化覆盖的关键路径
2. 给关键控件补齐稳定的 `accessibilityIdentifier`
3. 必要时补充无障碍标签或层级调整，让控件更容易被定位
4. 搭建最小自动化测试基础设施
5. 为首页到项目页、直接起稿、讨论起稿、正文编辑和基础回退准备自动化验证点
6. 做最小自测，确认测试可用、主界面不变形
