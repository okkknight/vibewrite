# TASK_20260412_030.md

## 本轮目标
本轮只完成：在现有 route-neutral backend 写作 transport envelope 上新增 `POST /v3/writes/edit`，让局部编辑也走同一条 bootstrap-token 校验链路，并返回 deterministic 的占位 completion 结果。

---

## 本轮背景

- `task/TASK_20260411_027.md` 已经把 `Backend/` Swift + Vapor 骨架、`GET /v3/health`、`POST /v3/client/bootstrap` 和 in-memory `deviceToken` 复用跑通。
- `task/TASK_20260411_028.md` 已经把 `POST /v3/writes/start` 跑通，并验证了 bootstrap-issued token 的校验、backend-only transport envelope 和 deterministic stub completion。
- `task/TASK_20260412_029.md` 已经把写作 transport envelope 做成 route-neutral，并把 `POST /v3/writes/continue` 接到了同一条 bootstrap-token 路径上。
- 现在 backend 里 `start` 和 `continue` 都已经通过同一套 envelope 和 token 校验链路工作，但 `edit` 路由还没有落地。
- 这一张 task 只负责把 `edit` 路由接上，不碰真实 patch、streaming、provider、数据库或 Redis。

## 本轮要做

- 在 `Backend/` 里实现 `POST /v3/writes/edit`
- 继续复用现有 backend-only 的 `WriteRequestEnvelope`
- 只接受 `action == .edit`
- 验证写作请求里的 `installationId` 和 `deviceToken` 仍然必须和 bootstrap 注册结果匹配
- 对局部编辑请求要求有效的选区信息
  - `selectionRange` 必须存在
  - `selectionRange` 必须能在 `project.documentText` 内解析成合法范围
  - `selectionText` 仍然作为请求上下文保留，不允许被静默丢掉
- 对合法请求返回一个 deterministic 的 `WritingAIResponse` 占位结果
- 补最小测试，覆盖成功路径、无效 token 路径，以及 `start` / `continue` 不回退的回归检查

---

## 本轮不要做
- 不做 streaming / SSE
- 不做 provider adapter
- 不做 prompt builder
- 不做 AI system prompt 拼装
- 不做真实 patch 应用
- 不做 quota 扣减
- 不做 request log 持久化
- 不做数据库或 Redis
- 不做 admin UI
- 不改前端
- 不修改 `VibeWriteShared` 里现有共享 DTO 的字段语义
- 不把 `edit` 额外拆成新的共享 request DTO

---

1. 先阅读 `docs/V3/PRD3.0.md`、`docs/V3/IA3.0.md`、`docs/V3/ROADMAP3.0.md`、`docs/V3/BACKEND3.0.md`、`docs/V3/API3.0.md`、`docs/V3/MIGRATION3.0.md`、`docs/V3/DEPLOY3.0.md` 和 `PROJECT_CONTEXT.md`，确认本轮只该继续推进第一条写作链路。

3. 把 `edit` 路由接到现有 bootstrap 设备注册结果上，完成设备校验后返回占位 completion 结果。
4. 加测试，确认 `edit` 可通、无效 token 被拒绝、`start` 和 `continue` 路由没有被这次扩展带坏。
