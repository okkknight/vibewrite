# TASK.md

## 本轮目标
本轮只完成：VibeWrite MVP 的 M3「Writing Project 与本地上下文驱动」。在不接真实 AI、不做服务端的前提下，把当前的静态/交互骨架升级为“每篇内容都是一个可继续协作的 Writing Project”，并在本地维护项目上下文、正文与最近项目记录，让用户关闭后再次进入时仍然可以继续上次协作。

---

## 本轮要做
- 定义 `Writing Project` 的本地数据结构，确保它能承载单篇内容的持续协作
- 定义 `Project Context` 的固定槽位并在本地维护
- 本地维护以下信息：
  - 当前正文
  - `intent_summary`
  - `style_constraints`
  - `current_goal`
  - `recent_decisions`
  - `working_memory`
  - `next_focus`
- 每轮 mock 协作后更新项目上下文，而不是只改一段临时文本
- 让首页“最近项目”改为真实读取本地项目数据
- 支持本地继续上次项目，关闭后再次打开仍能回到同一个 Writing Project
- 在写作项目页轻量展示上下文摘要，帮助用户和 AI 始终对齐
- 保持 M1/M2 的页面结构和产品气质不变

---

## 本轮不要做
- 不接真实 AI
- 不做服务端项目系统
- 不做复杂状态机
- 不做高度可配置的上下文面板
- 不做复杂版本树
- 不做多文档管理
- 不做模板、作品集、社区、语音输入、多端同步
- 不重构整体 UI 结构
- 不把项目做成重型项目管理工具

---

## 本轮主流程
1. 先按照 M3 里程碑文档复述目标与边界
2. 设计 Writing Project 和 Project Context 的本地数据模型
3. 选择并实现最小可行的本地持久化方案
4. 把首页最近项目与项目页上下文切换到真实本地数据
5. 把 mock 起稿、修改、继续推进后的上下文更新串起来
6. 确认重启后仍能继续上次项目
7. 做最小自测，确认项目上下文真的在帮助页面更稳，而不是只存一堆静态字段

---

## 建议的实现内容
以下不是唯一实现方式，但请保持目标一致：

- `WritingProject` 增加或明确本地持久化所需字段
- `ProjectContext` 拆成稳定的结构
- 本地项目存储层：
  - 项目列表
  - 当前活跃项目
  - 最近项目排序
  - 上次打开的项目
- 项目上下文更新器：
  - 根据 mock 协作结果更新 `current_goal`
  - 根据改写动作更新 `recent_decisions`
  - 根据写作阶段更新 `working_memory` 与 `next_focus`
- 首页最近项目卡片展示真实本地数据
- 项目页轻量上下文区展示真实本地数据

---

## 验收标准
- [ ] 每篇内容都能以 Writing Project 的形式持续协作
- [ ] 首页最近项目列表真实读取本地项目数据
- [ ] 用户关闭后再次进入，仍能继续上次项目
- [ ] 项目页上下文摘要来自本地项目上下文，而不是纯静态 mock 文案
- [ ] 每轮 mock 协作后，正文和项目上下文都会一起更新
- [ ] 页面仍然保持极简、清爽、写作协作器的气质
- [ ] 不引入重型状态机

---

## 实现要求
- 优先保守实现，不自行扩展需求
- 优先保证主流程闭环，不优先做附加功能
- 若遇到未定义需求，默认不实现
- 若发现需要大范围重构，先停止并说明
- 数据模型和持久化方案要足够简单、可维护、可继续扩展到真实 AI
- 不要把首页做成复杂项目库，也不要把项目页做成企业后台
