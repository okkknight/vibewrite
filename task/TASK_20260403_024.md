# TASK_20260403_024.md

## 本轮目标
本轮只完成一件事：**在不改变页面结构、不改变交互路径、不改变产品语义的前提下，重做整体视觉体系**，让 VibeWrite 从“灰白、漂、虚”的观感，变成一个**清晰可读、层级稳定、带有 Apple 系统审美的 macOS 产品界面**。

这轮只做视觉重绘，不做结构重构，不做功能扩展：

- 不改首页主入口结构
- 不改会话页的内容组织方式
- 不改 AI / 历史 / composer / 选区的产品语义
- 不改 patch / streaming / 状态逻辑
- 不改“宽屏正文中心 + 辅助层”的总体布局

你要解决的是一个很具体的问题：

- **按钮必须看得清楚**
- **正文必须看得清楚**
- **边栏必须看得清楚**
- **页面不能再白茫茫一片**

### 本轮的视觉原则
本轮优先遵循 Apple 官方推荐的系统视觉思路，具体体现在：

- 优先使用系统颜色语义
- 优先使用系统材料和系统面板感
- 优先使用标准按钮、标准分隔线、标准工具栏语义
- 优先使用 macOS 原生可读性，而不是自定义“极浅白纸”效果
- 优先让层级清楚、状态清楚、按钮清楚

### 当前代码的真实问题
当前页面存在明显的视觉问题：

- 整体过白，像“漂浮在空白里”
- 按钮和辅助文案对比度不够
- 边栏虽然有了，但视觉上仍偏淡，缺少系统侧边栏的稳定感
- 卡片、rail、正文和背景之间的层级区分不够明确
- 真窗口里看起来不够像一个人类可以长时间使用的产品

### 这轮要统一的判断
- 不要再把“功能完整”当成“视觉完成”
- 不要再把“灰一点、白一点”当成“系统审美”
- 不要再用低对比度去换“轻感”
- 页面必须先可读，再谈克制

## 本轮主流程

1. 先阅读 `docs/V2/UI2.0.md`、`docs/V2/Wireframes2.0.md` 和 `docs/V2/STRICT_ALIGNMENT_AUDIT.md`，确认本轮只做视觉重绘，不动结构。
2. 打开真实 app 窗口，分别观察 home、project wide、project compact 三个状态，记录当前白茫茫和可读性不足的问题。
3. 用 Apple 系统语义重绘视觉层：背景、卡片、按钮、分隔线、边栏、正文、输入区、标签、辅助说明。
4. 保持结构和交互不变，只替换视觉风格与可读性。
5. 针对首页和会话页都做一次真窗口复看，确认按钮、标题、辅助说明都清楚可读。
6. 跑 `swift test`。
7. 跑 `xcodebuild test -project VibeWrite.xcodeproj -scheme VibeWrite -destination 'platform=macOS'`。
8. 再次用真实窗口截图复核，确认视觉结果不再是灰白漂浮感。
