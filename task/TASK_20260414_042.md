# TASK_20260414_042.md

## 本轮目标
本轮只完成：把客户端正常运行态里残留的 provider 直连和 prompt builder 依赖清掉，让 app 的默认 AI 路径只剩后端网关和 stub / 测试兼容路径，不再把 `MINIMAX_*`、`WritingAIPromptBuilder`、`RemoteWritingAIClient`、`WritingAIClientFactory` 作为正常运行时依赖。

---

## 本轮背景

- `task/TASK_20260414_041.md` 已经把 backend 的运行态数据切到 PostgreSQL，并把 secret config 按加密 ciphertext 落库。
- `task/TASK_20260412_038.md` 已经把客户端正常 runtime 切到了 backend gateway，`BackendGatewayClientFactory` 已经是当前正常路径。
- 现在客户端源码里仍然保留着旧的 provider 直连配置和实现入口：
  - `Sources/VibeWriteApp/Shared/AI/WritingAIConfiguration.swift`
  - `Sources/VibeWriteApp/Shared/AI/WritingAIPromptBuilder.swift`
  - `Sources/VibeWriteApp/Shared/AI/RemoteWritingAIClient.swift`
- 现在客户端测试里仍然有直接引用旧直连路径的语义测试，需要在不影响当前行为的前提下，迁到更合适的 shared / backend 测试边界，或者删掉已经被新边界覆盖的重复断言。
- `docs/V3/MIGRATION3.0.md` 的 phase 5 已经明确要求：
  - 删除客户端密钥读取
  - 删除客户端 AI system prompt builder
  - 删除客户端 provider 直连
  - 清理旧 prompt builder 依赖
- 这轮不是再做一个过渡层，而是把客户端正常构建和正常运行里会让人误以为还要直连模型的残留全部收口。

---

## 本轮要做

- 清理客户端正常运行态的 AI 客户端选择入口，让默认 runtime 只保留 backend gateway 作为正常路径
- 从正常 app 代码里移除或收口 `WritingAIClientFactory` 对 direct-provider 的默认选择逻辑，确保 production path 不再依赖 `MINIMAX_*` 环境读取
- 清理正常 app 代码对 `WritingAIPromptBuilder` 和 `RemoteWritingAIClient` 的默认依赖，让它们不再构成当前产品的运行时边界
- 保留 `BackendGatewayClientFactory`、`BackendWritingAIClient`、`StubWritingAIClient` 和离线降级行为
- 重新安置仍然需要保留的旧语义测试：
  - 如果是 backend 相关 prompt / metadata 语义，迁到 backend 或 shared 测试
  - 如果只是重复验证旧 provider 直连行为，删掉或缩小到不会影响正常运行态的最小测试
- 更新 handoff / migration / index 文档，让下一位 agent 不再把旧 provider 直连当成 V3 的正常实现路径

---

## 本轮不要做

- 不做 backend 功能变更
- 不做新的 provider 接入
- 不做多模型
- 不做 prompt 多版本
- 不做数据库迁移
- 不做 Redis
- 不做账号体系
- 不做 RBAC
- 不做新的 API 路由
- 不做新的过渡抽象层
- 不为了兼容旧直连路径再新增一套默认运行链路
