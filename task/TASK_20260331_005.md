# TASK.md

## 本轮目标
本轮只完成：VibeWrite MVP 的 M4「真实 AI 接入与协作链路跑通」。在保留现有首页、项目页、本地项目上下文和自动化测试支撑的前提下，把当前 mock 写作引擎升级为真实 LLM 接入层，让直接起稿、先讨论再起稿、局部改写、继续展开、润色、主动建议都走真实模型；同时保持每轮请求前读取项目上下文、每轮响应后更新正文与项目上下文。

---

## 本轮要做
- 新增一个可注入的真实 AI client / provider abstraction，把 provider-specific 代码隔离在独立模块里
- 定义请求 / 响应数据结构，要求模型输出可稳定解析的结构化结果
- 把首页起稿、项目页发送、选区改写、继续展开、润色、主动建议都接到真实 AI client
- 每轮请求前传入当前 `WritingProject` 上下文
  - 当前正文
  - `intent_summary`
  - `style_constraints`
  - `current_goal`
  - `recent_decisions`
  - `working_memory`
  - `next_focus`
  - 当前动作与必要的选区信息
- 每轮响应后一起更新：
  - 正文
  - 对话
  - 项目上下文
  - 建议 chips
  - 最近项目更新时间
- 加入最小加载态和失败态，避免重复发送或失败后丢失正文
- 保留 mock / fake client 作为测试和预览注入，不把真实 API 绑死在 UI
- 让 UI tests 继续可稳定跑通，不能依赖外网或真实 key

---

## 本轮不要做
- 不做语音输入
- 不做多模型路由
- 不做复杂 prompt 配置后台
- 不做团队协作
- 不做复杂版本树
- 不做发布平台集成
- 不做高级设置面板
- 不做服务端项目系统
- 不把页面改成纯聊天产品
- 不把实现扩成通用 AI 平台

---

## 本轮主流程
1. 先按照 M4 里程碑文档复述目标与边界
2. 设计真实 AI 接入层和结构化输出 schema
3. 实现 provider adapter 和 prompt builder
4. 把 `WritingProjectView` / `VibeWriteAppFlow` 接到新 client
5. 增加加载态、错误态和重试入口
6. 保留 fake client / stub 流程，补齐单测和 UI test 注入
7. 做最小验证，确认真实 AI 结果会直接写入正文，并同步更新项目上下文

---

## 建议的实现内容
以下不是唯一实现方式，但请保持目标一致：

- 新增 `Shared/AI/` 目录，至少拆出：
  - `WritingAIClient` 协议
  - `WritingAIRequest` / `WritingAIResponse` 数据模型
  - `WritingAIPromptBuilder`
  - `RemoteWritingAIClient`
  - `StubWritingAIClient` 或等价测试替身
- 采用结构化响应，优先返回完整的：
  - `assistantMessage`
  - `documentText`
  - `summary`
  - `currentGoal`
  - `nextFocus`
  - `recentDecisions`
  - `workingMemory`
  - `suggestionChips`
- 将真实 AI 调用限制在一层，不要把网络请求散落在 View 里
- 保留 `MockWritingEngine` 作为测试/预览或过渡期实现，但运行时主链路应走真实 client
- 通过环境变量或配置注入 AI 运行参数，避免硬编码：
  - API key
  - model
  - base URL / provider setting
  - test mode / stub mode
- 给项目页增加最小加载提示和错误提示
- 给请求失败保留当前正文和输入内容，允许用户重试
- 为 prompt builder、响应解析、上下文更新补充 unit tests
- 为 UI tests 提供稳定的 stub 注入路径，确保自动化不依赖真实网络

## 验收标准
- [ ] 直接起稿、讨论起稿、局部改写、继续展开、润色都能通过真实 AI client 完成

- [ ] 每轮响应后正文和项目上下文会一起更新

- [ ] 失败态不会破坏当前正文或项目状态
- [ ] UI tests 和 unit tests 可以在 stub 模式下稳定通过
- [ ] 页面仍然保持极简、清爽、写作协作器的气质
