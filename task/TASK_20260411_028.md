# TASK_20260411_028.md

## 本轮目标
本轮只完成：在 `Backend/` 里接上第一条真正的写作请求链路，新增 backend-only 的写作 transport envelope，并让 `POST /v3/writes/start` 能在设备校验通过后返回一个 deterministic 的占位 completion 结果。

---

## 本轮背景

- `task/TASK_20260411_027.md` 已经把 `Backend/` Swift + Vapor 骨架、`GET /v3/health`、`POST /v3/client/bootstrap` 和 in-memory `deviceToken` 复用跑通。
- 现在的共享模块 `VibeWriteShared` 只保留纯契约和共享模型，`WritingAIRequest` 本身不应该被塞进 `installationId`、`deviceToken`、`requestId` 这类传输字段。
- V3 API 已经定义了写作请求入口，但 backend 里还没有任何写作路由或写作服务层。
- 这一张 task 只负责 `POST /v3/writes/start` 的第一条链路，不碰真正的 streaming、provider、continue/edit、数据库或 Redis。

## 本轮要做

- 新增 backend-only 的写作 transport envelope，用来承载：
  - `installationId`
  - `deviceToken`
  - `requestId`
  - `action`
  - `kind`
  - `project`
  - `userMessage`
  - `selectionText`
  - `selectionRange`
- 继续复用 `VibeWriteShared` 里的共享请求/响应模型，不修改它们的语义
- 实现 `POST /v3/writes/start`
- 验证写作请求里的 `installationId` 和 `deviceToken` 必须和 bootstrap 注册结果匹配
- 只接受 `startDraft` 这一种 action
- 对合法请求返回一个 deterministic 的 `WritingAIResponse` 占位结果
- 补最小测试，覆盖成功路径和无效 token 路径

---

## 本轮不要做
- 不做 streaming / SSE
- 不做 provider adapter
- 不做 prompt builder
- 不做 AI system prompt 拼装
- 不做 `continue` / `edit` 路由
- 不做 quota 扣减
- 不做 request log 持久化
- 不做数据库或 Redis
- 不做 admin UI
- 不改前端
- 不改 bootstrap 路由和 bootstrap 响应结构
- 不修改 `VibeWriteShared` 里现有共享 DTO 的字段语义

---

## 本轮主流程
1. 先阅读 `docs/V3/PRD3.0.md`、`docs/V3/IA3.0.md`、`docs/V3/ROADMAP3.0.md`、`docs/V3/BACKEND3.0.md`、`docs/V3/API3.0.md`、`docs/V3/MIGRATION3.0.md`、`docs/V3/DEPLOY3.0.md` 和 `PROJECT_CONTEXT.md`，确认本轮只该接第一条写作请求链路。
2. 在 `Backend/` 里新增 backend-only 的写作 transport models 和一个最小写作服务层。
3. 把 `POST /v3/writes/start` 接到现有的 bootstrap 设备注册结果上，完成设备校验后返回占位 completion 结果。
4. 加测试，确认合法 token 可通，非法 token 会被拒绝。

## 建议实现内容

以下不是唯一实现方式，但请保持目标一致：

- `Backend/Sources/VibeWriteBackend/Writes/WriteModels.swift`
- `Backend/Sources/VibeWriteBackend/Writes/WriteService.swift`
- `Backend/Sources/VibeWriteBackend/routes.swift`
- `Backend/Sources/VibeWriteBackend/Services/InMemoryDeviceRegistry.swift`
- `Backend/Tests/VibeWriteBackendTests/WriteStartTests.swift`
- `POST /v3/writes/start` 的请求模型保持 backend-only，不要把 `installationId`、`deviceToken`、`requestId` 加进共享 `WritingAIRequest`
- 路由只接受 `action == .startDraft`
- 占位 completion 结果使用 `WritingAIResponse`，内容必须可重复、可测试，并显式标记为 stub，不要偷偷引入 provider 语义
- 成功时返回当前请求对应的 `project` 状态镜像，避免改变正文和 metadata 语义
- token 不匹配时返回明确的 unauthorized 类错误
