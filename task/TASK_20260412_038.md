# TASK_20260412_038.md

## 本轮目标
本轮只完成：把客户端默认 AI 运行时切到后端网关，补齐本地 `installationId` / `deviceToken` 持久化，让 `startDraft`、`continueWriting`、`edit` 在真实运行时默认走 `Backend/` 后端，而不是继续直连供应商。正常运行时只保留一条后端写请求链路，metadata 直接来自同一次后端响应，不再额外发第二次 metadata 网络请求。

- 这一张 task 只负责**前端默认运行时切后端**，不改 backend 写作路由，不做后台 UI，不做数据库 / Redis，不做多模型，也不做文档格式迁移。

## 本轮要做

- 在 app 侧新增一个本地安装级身份存储，首次启动时生成并持久化 `installationId`，同时缓存后端签发的 `deviceToken`
- 这个身份存储必须跨重启保留同一个 `installationId`
- `deviceToken` 只作为后端设备校验凭证缓存，不承载账号语义
- 在 app 侧新增一个后端网关配置与 client：
  - 后端 API 基地址必须有单一来源
  - 真实运行时默认使用后端网关，不再默认读取 provider API key
  - `startDraft` / `continueWriting` / `edit` 默认走后端 `/v3/client/bootstrap` + `/v3/writes/start|continue|edit`
- 后端网关 client 必须实现现有 `WritingAIClient` 契约，保留当前 `VibeWriteAppFlow` 的流式 UI 入口
- 真实运行时只允许一条后端写请求链路：
  - prose 结果和 metadata 结果都来自同一次后端响应
  - 不能再像旧 provider 路径那样额外发第二次 metadata 网络请求
- 保留当前编辑器、本地文件、离线保存、recent documents、revision history 的行为不变
- 更新测试，覆盖：
  - 首次启动生成并持久化 `installationId`
  - `deviceToken` 能被 bootstrap 缓存并复用
  - 真实运行时默认使用后端网关 client，而不是 `RemoteWritingAIClient`
  - 离线 / 后端不可达时，AI 请求会走统一的网络不可用错误路径
  - stub mode 仍然可用于测试
