# TASK_20260412_032.md

## 本轮目标
本轮只完成：在已经跑通 `start` / `continue` / `edit` 且已经接上内存版 quota gate 的后端写作链路上，新增一个**内存版 request log store**，把三条写作路由的请求元数据统一记下来，供后续后台查询与持久化阶段复用。

---

## 本轮背景

- `task/TASK_20260411_027.md` 已经把 `Backend/` Swift + Vapor 骨架、`GET /v3/health`、`POST /v3/client/bootstrap` 和内存态 `deviceToken` 复用跑通。
- `task/TASK_20260411_028.md` 已经把 `POST /v3/writes/start` 跑通，并验证了 bootstrap-issued token 的校验、backend-only transport envelope 和 deterministic stub completion。
- `task/TASK_20260412_029.md` 已经把写作 transport envelope 做成 route-neutral，并把 `POST /v3/writes/continue` 接到了同一条 bootstrap-token 路径上。
- `task/TASK_20260412_030.md` 已经把 `POST /v3/writes/edit` 接到了同一条 bootstrap-token 路径上，并补了选区校验。
- `task/TASK_20260412_031.md` 已经把三条写作路由共用的**内存版 quota gate** 跑通了，日 / 周限额按 `installationId` 记账，拒绝请求不计数。
- 现在 backend 已经有 bootstrap、写作路由、quota gate 和 deterministic stub completion，但还没有统一的请求日志层。
- 这一张 task 只负责**内存版 request log store**，不做数据库、Redis、admin UI 或 request log 持久化。

## 本轮要做

- 在 `Backend/` 里新增一个**内存态** request log store
- 让 `POST /v3/writes/start`、`POST /v3/writes/continue`、`POST /v3/writes/edit` 的每一次请求尝试都能写入一条日志
- 记录的范围固定为**写作请求元数据**，不包含正文、摘要、`project.prompt`、`userMessage`、`selectionText` 或 AI system prompt 原文
- 只记录写作路由，不记录 `GET /v3/health`
- bootstrap 也先不纳入这一张 task，避免为 `bootstrap` 补额外请求标识而改变现有 API 结构
- 日志条目必须包含以下字段：
  - `request_id`
  - `installation_id`
  - `action`
  - `status`
  - `error_code`
  - `provider`
  - `model`
  - `duration_ms`
  - `token_in`
  - `token_out`
  - `created_at`
- 这一步的 provider / model 先使用当前后端的 deterministic stub 值，不要为了日志提前引入真实 provider 路由
- `token_in` / `token_out` 在这一阶段固定记录为 `0`，因为当前还没有真实 provider 计费
- 日志条目按请求完成时追加，确保成功 / 失败都能记到
- `status` 在这一阶段固定使用：
  - `accepted`
  - `rejected`
- `error_code` 在成功时为空，在失败时记录当前标准化错误码
- 只做进程内记账，后台重启后日志可以归零；这一阶段不要求持久化
- 给 store 保留一个可测试的只读快照接口，方便后续后台查询和单元测试
- 补最小测试，覆盖：
  - 成功写作请求会追加 accepted 日志
  - 认证失败或 quota 拒绝时会追加 rejected 日志
  - 日志字段与当前 request envelope / response 语义对齐

## 建议实现内容

以下不是唯一实现方式，但请保持目标一致：

- `Backend/Sources/VibeWriteBackend/Services/InMemoryRequestLogStore.swift`
- `Backend/Sources/VibeWriteBackend/Writes/WriteService.swift`
- `Backend/Sources/VibeWriteBackend/configure.swift`
- `Backend/Tests/VibeWriteBackendTests/RequestLogTests.swift`
- request log store 可以做成 `actor`，但必须保证同一条请求最终只会写入一条日志
- 日志写入应放在请求处理链路的收尾阶段，避免成功 / 失败路径记录不一致
- `WriteService` 里的日志写入不要改变原有的错误类型和 HTTP 状态码
- 这一阶段只记写作路由，不要顺手把 bootstrap / health 一起塞进来
- provider / model / token 计数先用确定的 stub 值，不要在没有真实 provider 的情况下脑补计费逻辑
- 先保留一个 `snapshot` / `allEntries` 之类的只读接口，后续再接后台查询时可以直接复用
