# TASK_20260402_017.md

## 本轮目标
本轮只做一件事：把 V2-M5 做成“更轻、更安静、更顺”的会话页体验收束。

这轮不是新增功能，也不是重做页面架构，而是把现有正文中心主线继续收紧，让用户在真实窗口里更容易持续写下去，而不是被辅助层、浮层和对比面板打断。

### 这轮必须达到的效果
- 空状态更像白纸，不像控制面板
- 选区浮层更轻、更贴近正文、更像上下文动作，而不是工具箱
- AI / 历史 / 版本这些辅助层收起与展开更自然，默认不抢戏
- 回退 / 对比 / 重试仍然线性可用，但不要把比较面板变成默认主角
- 输入与响应反馈更顺，但不能破坏 V2 的正文中心体验

这轮如果只做成样式微调、却没有把“选区浮层 / 辅助层 / 回退对比”的行为收束起来，就不算完成 V2-M5。

这些文档对 V2-M5 的共同要求是：

- 正文必须继续是第一视觉中心
- AI、历史、版本、选区工具都只是增强层，不能压过正文
- 辅助层应该按需出现，而不是默认像一组常驻面板
- 用户应该能持续写下去，而不是持续点按钮

### 现在代码的真实状态
- V2-M1 到 V2-M4 已经完成，正文中心、三动作主线、局部 patch、真实 AI、流式正文都已经在代码里。
- 当前会话页已经有了：
  - `EmptyDraftHint`
  - `SelectionPopover`
  - `assistantLayer`
  - `historyLayer`
  - `ComparisonPanel`
  - `undo / retry / compare`
- 这些能力都能用，但现在的感觉仍然偏“工具面板化”：
  - 空状态仍有一点卡片感
  - 选区浮层还可以更轻、更贴近选区
  - 辅助层展开后显得偏重
  - 成功执行动作后，比较面板会比较主动地跳出来

### 这轮要统一的判断
- 页面是否真的更像一张安静的文本编辑器
- 选区浮层是否真的变成轻量 contextual action
- 辅助层是否真的默认收起且不抢正文
- 回退 / 对比 / 重试是否仍然稳定，但不再强打扰

## 本轮要做

- 轻化空状态
  - 首页没有最近会话时，不要做成重卡片感面板
  - 正文页没有正文时，`EmptyDraftHint` 要更像一条轻提示，而不是一个控制区
  - 空状态只保留最少必要文案和一个清晰入口
  - 不要用大阴影、大边框、大块底色去强化空状态

- 轻化选区浮层
  - 选中文本后出现的浮层要更小、更轻、更贴近选区
  - 浮层里只保留真正必要的动作
  - 不能把选区浮层做成一个小型工具箱
  - 如果选中文本很长，浮层展示应压缩为更轻的摘要，不要撑成大块信息卡
  - 当 AI 请求进行中或正文已被锁定时，浮层应该清晰反映“当前动作不可继续”的状态，但仍然保持轻量

- 收紧辅助层展开 / 收起
  - `AI 辅助` 和 `历史与版本` 的展开头部要更像笔记本页眉，而不是控制面板标题
  - 收起态只保留简洁标题 + 一句轻摘要 + 低存在感的展开提示
  - 展开 / 收起时不要引起明显的视觉跳动
  - 默认状态仍然以正文为中心，辅助层不要自动抢占注意力

- 让回退 / 对比更克制
  - `撤销`、`前后对比`、`本段重试` 仍然保留在线性历史里
  - 但成功执行动作后，不要默认把比较面板自动顶到用户面前
  - `前后对比` 应该是显式动作，而不是每次成功修改后的默认展示
  - `重试` 应该恢复到可编辑、可继续写的状态，不要把页面带回重型对比模式
  - 保持 undo / retry / compare 的线性关系，不要引入版本树

- 收敛输入与响应反馈
  - AI 正在写作时，只需要轻量状态提示，不要把页面做成控制台
  - 输入框和正文的焦点切换要自然，失败时不要清空用户输入
  - 成功后可以清空输入，但不能让反馈中断正文阅读或选区操作
  - 继续保持 task016 的流式正文体验，不要退回到“等完成后才一次性跳变”

- 如果需要，轻调首页空状态
  - 只有在首页空最近会话时，才做非常轻的空列表提示
  - 不要扩展成新导览页
  - 不要为了 M5 重写首页骨架

- 具体视觉样式由 coder 自己判断，但必须遵守 `docs/V2/UI2.0.md` 和 `docs/V2/Wireframes2.0.md` 的“白纸优先、正文优先、增强层按需出现”原则。
- 如果需要做轻量动画或过渡，只允许用于减少跳动和提升顺滑感，不允许做夸张视觉效果。
- 如果需要调整布局，只做小范围收束，不允许把页面改回工作台或聊天产品。
