# TASK_20260402_018.md

## 本轮目标
本轮只完成一件事：把 V2 的会话页根骨架和视觉基底严格对齐到文档要求，先把“页面是什么”做对，再谈里面放什么。

这轮不是做功能补丁，也不是做局部美化，而是重建写作会话页的产品外壳：

- 中央正文必须成为唯一主视觉中心
- 页面必须恢复成文档定义的 shell 结构，而不是单列 notebook 堆叠
- 视觉必须转向 Typora 那种极简、白纸感、低存在感的编辑器气质
- 不能再使用“控制台感”“面板感”“工具箱感”的视觉语言去包裹正文

如果这一轮做完后，页面仍然像一组深色卡片或控制面板，而不是一张安静的白纸，那就不算完成。

---

## 本轮背景

### 必须对齐的设计依据
本轮必须同时参考：

- `docs/V2/PRD2.0.md`
- `docs/V2/IA2.0.md`
- `docs/V2/UI2.0.md`
- `docs/V2/Wireframes2.0.md`
- `docs/V2/STRICT_ALIGNMENT_AUDIT.md`

其中对本轮最关键的共同要求是：

- 正文是第一视觉中心
- 页面默认要像白纸
- 周边能力必须以辅助层形式存在
- 不允许把正文和辅助层做成等权工作台
- Typora 方向的核心不是“好看”，而是“干净、安静、没有工具台感”

### 当前代码的真实状态
- 当前 `WritingProjectView` 还是单列堆叠结构。
- `assistantLayer`、`historyLayer`、输入区、正文编辑区现在是纵向连续排布。
- 页面虽然功能可用，但视觉骨架和产品骨架都偏离了文档里的 shell 定义。
- 当前的视觉语言仍然更接近深色卡片式协作面板，不是 Typora 式白纸编辑器。

### 这轮要统一的判断
- 页面必须先像“编辑器”
- 再像“协作产品”
- 最后才像“有功能的正文工具”
- 任何让页面像控制台、卡片墙、工作台的实现，都算偏差

## 本轮要做

- 重建会话页的根布局
  - 恢复文档里的页面骨架，而不是继续用 `ScrollView + VStack` 纵向堆叠所有内容
  - 中央正文必须是主要空间
  - 辅助层必须进入真正的边缘区域或抽屉区域
  - 不要让辅助内容直接落在正文下方当作普通区块

- 建立 Typora 式白纸视觉基底
  - 主内容区必须呈现白纸 / 纸感 / 编辑器感
  - 颜色层级要克制，避免大面积深色底、厚边框、重阴影
  - 阅读宽度要自然，保留足够留白
  - 标题、正文、说明文字之间的层级必须像文档编辑器，不像产品控制面板

- 统一页面的最小视觉语言
  - 统一圆角、间距、分隔线、底色、阴影、字体权重
  - 所有主要区域都应遵循“轻、薄、纸感”的视觉方向
  - 不要在不同区域混用太多卡片语法

- 为后续侧栏任务留出正确的布局槽位
  - 左 AI 侧栏槽位
  - 右历史 / 版本侧栏槽位
  - 底部 composer 槽位
  - 顶栏轻量状态槽位
  - 本轮只搭好容器和视觉基底，不填入别的任务内容

- 让空态也遵守白纸原则
  - 没有正文时，正文区也必须像纸页而不是控制区
  - 空态提示只应作为很轻的一句话或很轻的一段说明
  - 不要把空态做成重卡片或引导页

---

## 本轮不要做

- 不做 AI 侧栏内容迁移
- 不做历史 / 版本内容迁移
- 不做底部输入区语义重构
- 不做状态模型修改
- 不做首页大改
- 不做 patch 语义修改
- 不做 streaming 语义修改
- 不做新的产品入口
- 不把正文页做成聊天窗口
- 不把页面做成控制台或工作台
