## 本轮目标
本轮只完成：在新的 `Backend/` 目录里新建 Swift + Vapor 后端工程骨架，先让后端可以独立启动，并提供 `GET /v3/health` 与 `POST /v3/client/bootstrap` 两个最小接口。

---

## 本轮背景

- `task/TASK_20260411_026.md` 已经把 `VibeWriteShared` 提升成独立共享目标，后端现在有了可直接复用的共享边界。
- 当前仓库还没有任何后端工程骨架，`find` 结果里只有 macOS app、共享代码、文档和 task 目录。
- 后端技术栈已经明确为 Swift + Vapor，不再讨论别的框架或语言。
- V3 的大方向已经确认：后端不存正文，不做账号体系，只做单人后台，先单模型。
- 这一张 task 只负责把后端工程和最小启动接口搭起来，不碰 AI 写作主流程，也不碰数据库持久化。

## 本轮要做

- 新建独立的 `Backend/` SwiftPM 工程，使用 Vapor 作为后端运行框架
- 接好对根仓库 `VibeWriteShared` 的本地依赖，方便后续共享 DTO 直接复用
- 实现 `GET /v3/health`
- 实现 `POST /v3/client/bootstrap`
- 用内存态设备注册表记录 `installationId` 到 `deviceToken` 的映射
- 让同一 `installationId` 在进程生命周期内重复 bootstrap 时返回同一个 `deviceToken`
- 为 bootstrap 返回一个固定结构的设备状态和默认限额摘要
- 补最小测试，确保后端可以独立跑通

---

## 建议实现内容

以下不是唯一实现方式，但请保持目标一致：

- `Backend/Package.swift`
- `Backend/Sources/VibeWriteBackend/main.swift`
- `Backend/Sources/VibeWriteBackend/routes.swift`
- `Backend/Sources/VibeWriteBackend/Services/InMemoryDeviceRegistry.swift`
- `Backend/Tests/VibeWriteBackendTests/BackendSmokeTests.swift`
- `GET /v3/health` 固定返回 `{"status":"ok"}`
- `POST /v3/client/bootstrap` 的请求字段固定为：
  - `installationId`
  - `appVersion`
  - `platform`
  - `deviceName`
- `POST /v3/client/bootstrap` 的响应字段固定为：
  - `deviceToken`
  - `deviceStatus`
  - `quotaSummary`
- `deviceStatus` 当前阶段固定为 `active`
- `quotaSummary` 先只包含当前默认日限额和周限额，不要提前做数据库或 Redis 扣减
- `deviceToken` 采用后端签发的随机不可预测字符串
- 同一 `installationId` 在进程内重复 bootstrap 必须返回同一个 `deviceToken`
- 后端包已经可以依赖 `VibeWriteShared`，但这次不要顺手开始改共享 DTO 的语义
