# TASK_20260414_041.md

## 本轮目标
本轮只完成：把 backend 当前仍在内存里的运行态数据一次性切到 PostgreSQL 持久化，并把 provider / admin secret 按加密方式落库。保留现有 API、路由、DTO、后台页面和限额语义不变，不做任何过渡性的双写或双读方案。

---

## 本轮背景

- `task/TASK_20260413_040.md` 已经把浏览器可打开的单页后台做完了，`GET /v3/admin` 现在已经存在。
- 现在 backend 的生产运行态仍然依赖 `InMemoryDeviceRegistry`、`InMemoryQuotaLedger`、`InMemoryRequestLogStore`、`AdminSecretStore`、`AdminSystemPromptStore` 和 `AdminSessionStore`。
- `docs/V3/DATA3.0.md` 已经把后端数据口径定成 PostgreSQL，并要求 secret config 按 ciphertext 存储。
- `docs/V3/DEPLOY3.0.md` 已经要求 backend 读取数据库连接和 secret encryption key。
- 这轮的目标不是再搭一层过渡抽象，而是把当前可运行 backend 的存储基线正式切到 PostgreSQL。

---

## 本轮要做

- 在 `Backend/` 里接入 PostgreSQL 支持，固定使用 Vapor 原生的 PostgreSQL 数据层，完成数据库连接、配置和迁移接入
- 把当前所有需要留存的 backend 状态迁移到 PostgreSQL：
  - devices
  - request logs
  - quota rules
  - quota usage daily
  - quota usage weekly
  - secret config
  - system prompt config
  - admin sessions
- 用数据库实现当前内存态存储的等价能力，并直接替换生产路径上的内存 store
- 把 provider secret 和 admin secret 改成加密存储
  - 读取环境变量 `ADMIN_SECRET_ENCRYPTION_KEY`
  - 使用它对 secret config 的可逆明文做加密后再入库
  - 数据库存储只保留 ciphertext
  - 读取时解密回当前运行态需要的明文
- 保持现有 public API 和 admin API 不变：
  - `/v3/client/bootstrap`
  - `/v3/writes/start`
  - `/v3/writes/continue`
  - `/v3/writes/edit`
  - `/v3/admin/*`
- 让以下行为继续按现有语义工作，只是持久化来源变成 PostgreSQL：
  - bootstrap 幂等
  - device block / unblock
  - quota 统计和更新
  - request log 写入和查询
  - admin login / logout
  - admin secret / system prompt 读写
  - admin session 校验

---

## 本轮不要做

- 不做前端改动
- 不做新 API 字段
- 不做 Redis
- 不做账号体系
- 不做 RBAC
- 不做多模型
- 不做 prompt 多版本管理
- 不做云文档
- 不做 SQLite fallback
- 不做双写 / 双读过渡方案
- 不保留一套并行的内存生产主实现

## 建议实现内容

以下不是唯一实现方式，但请保持目标一致：

- `Backend/Package.swift`
- `Backend/Sources/VibeWriteBackend/configure.swift`
- `Backend/Sources/VibeWriteBackend/Persistence/` 下的新数据库模型、迁移和仓储实现
- `Backend/Sources/VibeWriteBackend/Services/InMemoryDeviceRegistry.swift`
- `Backend/Sources/VibeWriteBackend/Services/InMemoryQuotaLedger.swift`
- `Backend/Sources/VibeWriteBackend/Services/InMemoryRequestLogStore.swift`
- `Backend/Sources/VibeWriteBackend/Admin/AdminModels.swift`
- `Backend/Sources/VibeWriteBackend/Admin/AdminSessionStore.swift`
- `Backend/Sources/VibeWriteBackend/Admin/AdminRoutes.swift`
- `Backend/Sources/VibeWriteBackend/Writes/WriteService.swift`
- `Backend/Sources/VibeWriteBackend/BootstrapModels.swift`
- `Backend/Tests/VibeWriteBackendTests/`
- 如果需要测试数据库配置，可以新增专门的测试辅助代码，但不要把生产实现退回到内存模式

建议的数据库落表范围：

- `devices`
- `request_logs`
- `quota_rules`
- `quota_usage_daily`
- `quota_usage_weekly`
- `secret_configs`
- `system_prompt_configs`
- `admin_sessions`

secret config 的加密规则建议固定为：

- 使用 `ADMIN_SECRET_ENCRYPTION_KEY` 作为对称加密密钥来源
- 使用可逆加密保存 ciphertext
- 数据库里只存 ciphertext，不存明文
- 启动时如果加密 key 缺失或无效，直接 fail fast
